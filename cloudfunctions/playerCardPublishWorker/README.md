# 球员卡发布续跑

部署前从正式仓库运行 `node tools/build-player-card-worker.cjs`，复制统一生成器、发布器、读取器、字体及现行数据中心模块；不要另改这里的生成副本。安装 package.json 依赖，并在 Linux 发布包中包含 resvg Linux x64 gnu 原生模块。

Event 函数，Nodejs18.15、512 MB、60 秒，无 HTTP 路由。客户端函数规则 `{"invoke":false}`；只允许 IAM 运维调用及 timer。每分钟检查三个卡种的待发布任务；单次有时间预算，事务租约防止与后台重复处理。无任务时不扫描球员。

`audit` 只读核验；`synchronizeActive` 为已发布卡种补齐现有名单卡，不改变模板版式或主动发布其他卡种。常规发布由平台负责人会话创建任务，失败保留旧活动指针；修复后从后台重试。

首次源图允许经用户确认的现有报表/名单照片，标记 `legacy_roster`。稳定球员 ID、现行正式积分和测试来源过滤仍为必需条件。后续首次补齐标准照片不受第二次更换照片的积分门槛限制。自动制卡不设置公开许可。
