# 赛小蜂足球仓库巡检

## 执行

```powershell
node tools/repo-status.mjs
```

脚本已入库，只读，不修改任何文件。不要用 `git status`、`git branch -a` 手工重拼一份，直接跑脚本。

## 判读

| 输出 | 含义 | 处理 |
|---|---|---|
| `main ahead=N behind=0` | 本地 `main` 有 N 个未推送提交 | 确认这些提交属于哪条线，需要时推 `github`，不要强推 |
| `main behind=N` | 本地 `main` 落后远端 | 提醒用户先同步，切换前检查工作区是否干净 |
| `preview behind=N` | 测试线落后 | 与正式线差异属于正常发布节奏，只在发布前后核对 |
| 工作区非 0 | 有未提交或未跟踪文件 | 报告文件列表，不自动提交；确认归属后由用户决定 |
| `有改动: N` 个 worktree | 有会话可能正在进行 | **禁止**删除、禁止 `worktree prune` 扫掉有改动的目录 |
| `已丢失: N` | worktree 目录被外部删除 | 可 `git worktree prune`，属清理注册表 |
| 线上 `Last-Modified` | 部署时间 | 与最新提交时间对比，源码更新但线上更旧说明尚未发布 |

## 红线

- 只读巡检。不提交、不推送、不部署、不删除 worktree、不清理文件。
- 需要清理时，先把 `git diff` 与未跟踪清单导出到仓库外归档目录，再动 worktree。
- 分支被 worktree 占用（`main`、`preview`）时不得 `checkout`，不得强删分支。
- 发布走 `功能分支 → preview 验收 → main → 正式`，巡检只判断状态，不代替发布流程。

## 汇报

先给结论一句话（能否安全开工 / 有无阻塞），再给三条以内的关键事实，最后列出建议动作。不要粘贴脚本完整输出。
