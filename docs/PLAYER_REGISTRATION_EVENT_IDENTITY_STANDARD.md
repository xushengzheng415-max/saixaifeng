# 球员注册、球员卡与赛事身份核验标准

状态：2026-10-03，已由产品负责人确认作为足球小程序、服务号 H5、PC 管理后台和云函数的统一产品标准。当前实现状态按 `CURRENT_STATUS.md` 和本文“实施边界”分别核对；文档确认不代表代码已上线。

## 核心原则

- 球队建档与赛事资格核验分开。加入球队不要求身份证、人证核验或保险资料。
- 球员卡是球员注册体验的核心。照片用于制卡和球队资料展示，不用于自动认定赛事资格。
- 证件收集由赛事或组别配置决定，默认不收集。不得为省事而默认强制所有赛事上传身份证。
- 身份证用于投保与人证核验是不同目的。投保资料不自动变成“人证核验通过”。
- 没有开启对应要求时，不展示证件步骤、不创建待办、不调用 OCR 或人脸服务、不消耗识别额度。
- 赛事工作空间中的通知必须带赛事、组别、球队和球员范围，点击后进入对应的待办或球员资格页。

## 球队球员注册

1. 成人球员由本人登记；青少年由家长或监护人登记。微信登录/手机号验证用于确定账号和通知接收人，不替代政府证件核验。
2. 填写球员姓名、球队归属和必要的基础资料。球队球员库保留长期档案；参赛名单由球队在具体赛事中单独提交。
3. 进入制卡体验：选择适用模板，拍摄或上传正面头像和标准形象照，调整裁切并预览球员卡。照片不完整时可先保存基础档案，之后从球队球员资料继续制卡。
4. 成人模板使用当前获准的金、银、铜等卡面与等级规则；注册人不能通过自行选择模板改变服务端核定的卡级。家长可替孩子完成基础制卡，青少年专属卡面另行设计，未上线前不得显示为可用模板。
5. 球队审核只审核入队关系及球队资料，不审身份证。制卡照片及头像不得作为参赛身份核验的唯一证据。

## 赛事证件要求

赛事或竞赛组别使用单一“证件要求”预设，默认“不要求证件”：

| 预设 | 上传内容 | OCR/人证核验 | 赛事处理 |
|---|---|---|---|
| 不要求证件 | 无 | 不调用 | 正常报名，直接进入主办方名单审核 |
| 仅用于统一投保 | 身份证正反面 | 不调用 OCR 或人脸核验 | 受限保存，只供获授权的投保处理人员使用 |
| 人证资格核验 | 按证件类型上传必要页面 | 按既定人证流程核验；异常交主办方复核 | 核验通过后满足本组资格要求 |
| 投保并核验 | 同一份证件材料 | 按人证流程核验 | 保险处理与资格核验分别记录授权及结果，不重复要求上传 |

只有“人证资格核验”或“投保并核验”可以额外启用“赛前电子参赛证扫码”。该选项只在身份核验已启用时可选；关闭时不得签发或要求扫码。标准形象照按组别另行设置，关闭时可后补且不能阻塞报名。

主办方可以设置平台默认建议，但每届赛事必须能明确看到本届证件预设。默认关闭；主办方可按竞赛规程选择，不得把身份证要求隐藏在球队注册流程中。

## 证件、保险与人证数据

- “仅用于统一投保”走独立的受限资料流程，不调用 OCR、不建立人证通过状态，不把证件字段写进球队公开档案。
- “人证资格核验”按已定的人证流程执行；身份证正反面、护照或其他证件所需页面由证件类型决定。百度 OCR 只在明确启用识别并取得授权后调用。
- 两种用途同时启用时可以复用同一上传文件，但必须分别记录用途授权、接收范围、处理状态和保留期限。
- 原始证件材料只向对应赛事授权人员开放，按既定期限加密保存并删除；球队普通管理员、球员卡页面和裁判普通页面不得查看证件原图或身份证号明文。
- 数据状态必须明确区分“不要求”“待上传”“已提交待审核”“已通过”“需补充”“已退回”；不得将证件已上传写成身份已通过，也不得把前三步阶段提示为整份球员资料审核成功。

## 赛前电子参赛证与扫码

- 只有赛事启用电子参赛证扫码后，已进入本场首发或替补阵容的球员才生成本场有效凭证。
- 二维码使用签名、短时、比赛范围令牌，不包含姓名、身份证号或证件照片；裁判扫描后读取最少必要的球员姓名、头像、球队、阵容和核验状态。
- 需要身份确认但球员未带实体证件时，可按赛事授权使用已留存的人脸参考进行现场人脸比对。必须明确展示授权用途；拒绝或设备不可用时走人工核验，不伪造自动通过。
- 青少年赛事的球员资格与监护人授权沿用同一赛事规则；家长负责登记或授权，现场核验对象仍是球员本人。
- 没有开启扫码核验的业余赛事不展示电子证任务，裁判按赛事规程人工处理。

## 通知与审核

- 球员建档通知与赛事资格任务分开。球队只收到入队、基础资料或球队审核消息；赛事身份任务发给该赛事/组别负责人。
- 只有存在可执行操作时才创建“待处理”任务；提示必须明确接收对象、赛事/组别、球员、当前状态和下一步入口。
- 人证资料等待审核时显示“等待主办方审核”；完成身份证核验不等于球队入队审核完成。球队审核只在球队资料确实提交后出现。
- 投保资料状态与人证审核状态独立；核验关闭的赛事不得收到身份证待办。

## 实施边界

- 当前团队邀请默认强制身份证和照片的旧逻辑应删除；活动/组别的核验开关是唯一赛事要求来源。
- 当前赛事规则表单、正式名单门禁、证件邀请链接、受限保险文件、电子证二维码和裁判扫证必须使用同一赛事/组别配置，不能各自设置默认值。
- 球员卡模板在注册入口的接入、保险专用证件上传（不 OCR）、赛事范围 H5 核验链接、青少年电子证现场核验与人脸备用流程均须完成前后端闭环后，才能标记为上线。
- 微信小程序版本号和上传时机由产品负责人指定。当前版本号、上传包、体验版和正式版状态以实际记录为准。
