# 主办方赛事子账号侧边栏权限

状态：开发候选；本文件的新十模块授权尚未发布。线上测试版仍使用补录成绩、新闻编辑、新闻发布三项旧授权。

## 授权边界

- 授权对象是已核验手机号对应的自然人账号，作用域固定为一个机构下的一项赛事。
- “全部权限”在保存时展开为当前十项权限，不存永久通配符；后续新增模块须再次授权。
- 十项与主办方赛事侧边栏一致：赛事主控制台、竞赛管理、报名管理、球队管理、抽签与分组、比赛管理、赛果管理、新闻中心、裁判管理、赛事设置。
- 不含账号管理、平台运营后台、数据中心、球员卡系统，也不授予其他赛事或机构权限。
- 菜单与路由只作交互控制；数据库查询、云函数、HTTP 中转按账号、机构、赛事、模块、具体动作在服务端独立核验，未映射动作默认拒绝。
- 旧授权 `result.supplement` 映射为赛果管理菜单、`news.edit/news.publish` 映射为新闻中心菜单；旧授权实际操作范围保持原样，不因菜单合并自动扩大。

## 接口改造门槛

| 权限 | 页面 | 服务端检查重点 |
|---|---|---|
| `event.dashboard` | 赛事主控制台 | 仅当前赛事的聚合读取 |
| `event.competition` | 竞赛管理 | 本赛事组别、规程、方案定版 |
| `event.registration` | 报名管理 | 本赛事报名、参赛关系、审核及邀请 |
| `event.teams` | 球队管理 | 本赛事参赛球队及名单；不得越权写长期球队资产 |
| `event.draw` | 抽签与分组 | 本赛事分组、签位、对阵 |
| `event.matches` | 比赛管理 | 本赛事赛程和赛前/赛中主办方操作；裁判现场写入仍独立 |
| `event.results` | 赛果管理 | 本赛事补录、复核、纠错和榜单发布；保留原始记录 |
| `event.news` | 新闻中心 | 本赛事草稿、生成、发布和撤回；遵守赛果版本 |
| `event.referees` | 裁判管理 | 本赛事裁判邀请、排班和审核；不等于裁判本人执法身份 |
| `event.settings` | 赛事设置 | 仅本赛事设置及明确受控的删除/锁定操作 |

当前页面和授权服务已接受十项权限；**上述各模块的完整服务端操作门禁尚未接通，故不能发布此候选界面或向用户发放新权限。**

- 已在 PC 通用数据查询、中转函数、赛事资料读取、新闻与赛果、组别/报名/裁判相关服务中增加赛事范围与动作校验。未知动作拒绝，停用授权后重新校验。
- 已补赛事内建队的球队与参赛关系事务写入；图片与分片上传增加赛事、模块及上传会话操作者检查。数据中心的 PC 子账号读取限定为当前赛事，球员卡和转会操作不开放给赛事子账号。
- `uploadFile` 的直接调用入口已在本地候选增加登录会话和子账号赛事授权校验，部署前仍需核对全部实际调用方，避免影响既有上传流程。
- 尚需逐页核对各模块所有实际读写路径。机构级球员库与球队主账号分配已对赛事子账号隐藏；全局裁判资格审核和虚拟裁判库写入也已隐藏并在通用数据库入口拒绝。赛事子账号可继续使用本赛事的临时裁判确认、邀请和排班。之后使用真实主账号和子账号验收。活跃的球员卡、球员注册线上包必须在部署前重新下载比对；此候选不得直接覆盖线上包。
- 竞赛管理页已增设独立规程上传入口；赛事资料页只对同时拥有竞赛管理权限的子账号显示规程操作。单项权限仍需与服务端实际动作逐项验收。
- 抽签页对子账号已改走受控的 `generateSchedule.resetPairings`：先阻止已排赛、已发布或有赛果的重抽，再删除本组占位比赛并更新汇总状态；通用比赛删除仍不授予抽签权限。该组合流程还需真实账号验收，不能仅凭本地构建判断完成。
- 旧 `result.supplement` 授权进入赛果菜单时转到专用补录页，不能通过深链接进入积分发布或纠错页；新 `event.results` 才对应完整赛果模块。
- 报名管理与球队管理复用同一 PC 页面。报名单项授权现可在服务端受控地预建本赛事球队，但报名页跳转的球队详情、原始报名资料和部分长期资料操作仍需拆分为本赛事只读审核与球队管理写入；单项授权尚未验收。
