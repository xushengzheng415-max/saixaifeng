# 赛小蜂足球发现一级页开发交接

交接对象：TRAE 页面开发。日期：2026年10月26日。版本：一级页限定版。

## 01 本次任务和范围

只实现球队端小程序“发现”一级页面及其动态、赛事、约球三个同页视图。动态与约球按本文标准组织内容和操作；已经存在的记分、邀约、赛事中心、报名签到等页面只做入口对接，不重复开发。本文没有授权生产发布、修改云函数、迁移数据库或调整转会规则。

最新导航固定为“动态／赛事／约球”，默认动态。底部仍为“首页／赛事／球队／发现／我的”，发现选中；转会市场不成为顶部分栏或底部导航。顶部唯一高权重主操作为“记一场”。球队招募属于动态，不出现在赛事卡片或转会市场中。

（2026-10-26 用户追加确认）发现只做身价展示：赛事卡片不再出现转会市场入口与转会窗口倒计时，报价、收件箱、谈判、主办审核、租借买断与自由签约全部收进“本地赛事 → 具体赛事 → 转会中心”三级链路，由赛事转会中心任务承接。

| 分类 | 本轮执行范围 |
| --- | --- |
| 做页面 | D01 通用页框；D02 动态内容流；D03 赛事卡片；D04 约球列表。四个视图复用同一发现路由 |
| 做页面内交互 | 页签、筛选、刷新与续页、状态提示、明确的发布与分享入口、已有跳转与返回恢复 |
| 只做设计标准 | 动态发布、评论、招募资料、约球发布与海报选择的字段和权限；数据接口缺失时不得假装已接通 |
| 只对接既有功能 | 记一场、已记录战报、现有邀约创建、赛事中心；报名签到等由其原页面承接 |

本轮用户已经明确了导航、招募归属和赛事卡片两个入口（赛事中心＋只读球员身价）；本文标为“设计默认”的细节仅用于一级页实现，不升级为收费、身份或数据归属规则。当前小程序源码已有球场／成长模式，本次不删除其业务数据或改变授权；新发现一级页不继续展示演示成长统计，成长原入口的产品迁移需另任务处理。

## 03 D02 动态功能设计标准

动态由战报、球队动态、球队招募三种内容组成。设计默认按发布时间倒序，同城与关注筛选属于一级页视图状态；若关注关系服务尚不可用，必须单列为未接入，不能伪造关注结果。内容范围由服务端公开授权裁剪，不能把“我记录的友谊赛”直接当成全平台动态。

| 内容类型 | 必要展示字段 | 操作与去向 |
| --- | --- | --- |
| 战报 | 发布球队队徽和名称、发布时间、比赛性质、双方名称、可信比分、照片或海报、来源状态 | 查看既有战报；点赞、评论、分享按已接入能力启用；自报友谊赛显示友谊赛，不冒充官方赛果 |
| 球队动态 | 发布球队、时间、正文、授权照片、内容状态 | 查看正文或图片；发布身份固定为当前有权限球队，实际操作者留在后台 |
| 球队招募 | 招募球队、适用组别、城市、位置、人数、说明、有效状态 | 在动态流展示；进入已登记球队或招募承接页；本轮不新建转会／签约流程，也不直接公开电话 |

发布入口为动态栏内低权重文字“发布”，不能抢占顶部“记一场”。菜单仅包含球队动态和球队招募；战报优先从已有比赛记录生成后发布。正文、图片数量和大小限制读取现有上传组件与服务端配置，不能前后端各设不同上限。

评论与发布必须校验已验证手机号的自然人账号及当前球队权限。前台可展示球队／岗位或允许的昵称，后台记录真实 actorUserId；不能只存球队名。游客可以浏览允许公开内容，点击写操作再登录，登录后回到原动态；未授权用户不能冒充球队发表评论。审核中内容不进入公开流，失败可重试且不重复创建。

点赞要可取消并防重复；列表计数以服务端为准。评论失败保留输入；删除、隐藏、举报的权限与处置接口须复用既有服务，缺失时列出接口缺口。本轮“只一级页”不新增动态详情、发布详情或评论管理页面；可复用已有弹层，或对接已注册路由。

### J01 动态浏览与 J02 内容操作

J01：进入发现 → 动态 → 同城／关注筛选 → 查看战报或照片 → 返回保留当前位置。J02：有球队权限者打开发布菜单或评论 → 既有承接组件 → 服务端确认成功后刷新对应项；失败保留原输入，不先显示成功。

## 04 D04 约球功能设计标准

约球采用已确认的邀约海报轻流程：发起方登记比赛意向，分享海报给微信群，球员扫码报名，比赛日签到。不是双队撮合平台，不要求对手先注册或点击同意才能发布，也不建设场地交易、代收费用或对方账号审批链路。

| 一级页字段 | 显示与状态标准 |
| --- | --- |
| 发起信息 | 邀约ID、真实发起球队名称与队徽、发起时间；多队账号显示当前操作球队 |
| 比赛信息 | 标题或组合名称、赛制与适用组别、时间、区域和场地状态。缺失显示待定／待协商，不补造场地或日期 |
| 报名信息 | 已报名人数、限额、截止时间、报名中／已满／截止／取消等真实状态；未设限额不得显示成0人限额 |
| 操作入口 | 发起约球、查看邀约、分享海报；发起人可进入既有报名签到管理。非发起人不显示管理入口 |

J03：约球栏 → 发起约球 → 已有创建流程 → 选择海报版式 → 生成并分享海报。既有创建入口与海报入口的实际参数应读源码核验，不能凭图稿猜测新路由。当前已核对发现页 onStartCreate 跳转 `/pages/tournament/quick-create/quick-create`；独立邀约页已注册于 `/pages/discover/invite-create/invite-create`。二者既有衔接顺序先按当前调用执行，本轮不擅自并成新接口。

三款海报“绿茵球场／清爽白／夜赛黑金”为已设计候选，切换只改呈现，不改变时间、地点、报名上限或真实比赛性质。海报文字由原生组件绘制，小程序码绑定真实邀约ID；禁止把图稿中的预留码当可扫码成品。海报和创建页仅交接设计要求，本轮不重做其二级页面。

已满、超过截止或取消时，报名按钮由既有页面与服务端共同控制。一级列表只呈现状态，不能仅靠本地倒计时放行报名。签到提醒遵循既有订阅消息能力，未配置时降级为分享海报。友谊赛记分仍从“记一场”进入；正式赛事比分继续走授权裁判链路。

## 05 D03 赛事卡片与外部入口

赛事栏展示当前可公开的同城赛事，可按成人／青少年等已有字段筛选。每张卡包含封面、赛事名称、类别／赛制、日期、区域、主办方与状态；缺封面用统一品牌底图，不用随机图冒充真实赛事。列表使用稳定 tournamentId，不依名称绑定。

每张卡只有两个独立入口：赛事中心、球员身价。点击按钮不得同时触发卡片整体点击；两者都携带该卡片的赛事ID。发现只做身价展示，不出现转会市场入口，也不出现转会窗口状态或倒计时；窗口、报价、收件箱、谈判、主办审核、租借买断与自由签约都在“本地赛事 → 具体赛事 → 转会中心”三级链路，由赛事转会中心任务承接。

| 入口 | 行为 |
| --- | --- |
| 赛事中心 | 打开既有赛事中心承接页，参数为该卡片的赛事ID |
| 球员身价 | 打开新增只读页 `miniprogram/pages/tournament/valuation/valuation?id=<赛事ID>&name=<编码后赛事名>`；页面没有任何报价、签约、审核或编辑按钮 |

身价页只有一个数据来源：`getMiniWorkspace` 的 `tournamentPlayerValuations` 只读投影。服务端已校验当前工作空间能访问该赛事，才返回数据；页面不自算身价、段位或名单。

| 项目 | 规则 |
| --- | --- |
| 名单范围 | 只取本赛事已审核名单（`roster_snapshots`，兼容旧 `rosters`）；草稿、已删除、他赛、测试／虚拟数据不进列表 |
| 金额来源 | `player_valuations` 中 `computedAt` 最新的一条快照；同一球员旧快照不覆盖新快照 |
| 青少年 | 只显示“不公开”，不返回金额与段位 |
| 未测算／待评估 | 显示“待评估”；不用 0、示例数字或旧快照冒充已测算 |
| 分页与筛选 | 服务端单页 20 条，支持竞赛组别、球队与关键词；页码越界收敛到末页，不静默截断 |
| 读取失败 | 显示原因与重试；名单集缺失标注“名单未登记”，与真实空名单分开，不降级成“暂无球员” |

J04：赛事卡片 → 赛事中心使用当前小程序中已注册的 `/pages/public-tournament-center/index?hash=event-<编码后的赛事ID>`，由既有承接页打开服务号赛事中心。本地 discover.js 仍含旧的 `public-tournament-center/public-tournament-center` 路径，但本次核对 app.json 和文件目录仅存在 index，交接时必须修正调用处并验证返回；不能照抄旧路径。

身价页与转会市场是两件事：身价页只读展示，转会市场的正式页面路径、模块授权和参数合同由赛事转会中心任务维护。发现侧只保留 J05 入口适配点（按钮 → 身价页），不得跳旧设计HTML、不得假装打开转会市场，也不得把身价展示当成市场可交易状态。

给页面提供独立数据适配层，把“一级列表展示模型”与当前服务返回字段隔开。建议模型至少有稳定ID、类型、发布主体、图片、业务来源、时间、展示状态、真实操作能力与跳转目标；这些是适配模型建议，不是已部署云函数action名。

Q01 动态与约球公开列表、评论／点赞／招募提交的真实接口与授权范围需开发前核验。接口未就绪时只在隔离开发预览中提供明确标注的fixture；正式环境不得写死示例内容或直接放开客户端数据库权限。Q02 已收敛：发现不再读取转会窗口，也不再承载转会市场；身价读取由 `tournamentPlayerValuations` 承接，其余窗口与市场合同由赛事转会中心任务维护。

登录、机构成员关系、工作空间和球队授权沿用项目现有机制。切换账号或球队后清理上一上下文的私有缓存，重新读取对应列表；浏览公开内容不授予发帖、报名管理或转会权限。WXML只用简单插值、简单取反及简单或，所有比较、标签、金额、身价状态和按钮flag在js中预计算。

## 07 状态验收与给TRAE的执行任务

| 场景 | 必须看见的结果 |
| --- | --- |
| 首次加载／刷新／续页 | 只为当前栏显示加载；旧数据可保留并标刷新。续页防重复请求，结束后明确无更多，不静默截断 |
| 空数据 | 动态“暂无球队动态”；赛事“暂无符合条件赛事”；约球“暂无约球邀约”，提供当前权限允许的下一步；身价页区分“暂无名单球员”与“名单未登记” |
| 网络失败 | 当前栏显示原因与重试，不假装成空；图片失败不拖垮正文；身价读取失败显示重试，不显示 0 或示例金额 |
| 游客／无球队／无权限 | 保持允许的浏览；写操作先登录或选择有权限球队；非发起人看不到签到管理与删除；无权赛事不返回身价 |
| 重复点击／返回 | 提交中禁用；成功以服务端结果更新；取消不写数据；返回保留栏目、筛选与滚动位置 |
| 时间与内容 | Asia/Shanghai展示。报名人数、截止、取消临界正确；长队名／缺图／缺比分可读，未知不显示为0；青少年身价只显示“不公开” |

交付必须说明实际修改文件、哪些接口已经接通、哪些只完成前端状态、测试结果和仍存在的接口缺口。不要把图稿生成、mock点击或本地编译称为线上业务完成。未获当前任务发布指令前，不上传微信开发者平台、不提交审核、不部署云函数或正式网页。
