# 登记照片制卡弹窗与号码就地提示

2026-10-18。用户要求：拍照或上传后弹出生成初始球员卡的动画，生成后调整大小、上下左右并确认；号码重复须在输入框下用中文提示。

## 行为

- 服务号球员登记表拍照/相册选图后立即弹窗，照片处理、初始卡生成使用对应加载动画和状态，不编造百分比。完整成卡来自平台已发布模板与统一渲染器，不在网页重排卡面。
- 弹窗可调人像大小、上下左右、复位，再“确认使用”。确认前不新建/认领球员，只保存私有临时构图；仍需授权与正式提交。由最终提交触发重开预览时显示“确认登记”，确认后继续该次提交。
- 照片失败、生成失败、返回修改、取消、超时及重试保持独立状态；取消处理中不会被迟到结果重新打开。模板/资料/照片变化需重新确认；同照片改资料保留原构图。
- 号码输入后防抖检查、离开字段检查，重复在输入框下显示如“21号已被本队使用，请更换号码”，输入框标红；不重复在页面顶部显示相同错误。正式提交仍检查完整有效号码库，防止期间被别人占用，冲突保留资料及照片供修改。
- 390×844使用方向十字控件；320×568短屏改为一排方向控件。四个方向、确认按钮均可见，按钮文字上下居中，整卡等比完整显示。尊重系统减少动态效果设置。

## 约束

既有球员读真实生涯；新档案仅由服务端已验证表单生成未来稳定ID，内部只读方法playerCardForAuthorizedRegistrationDraft复用统一读取/buildPlayerCard，不创建球员或正式卡库，不把未知、故障或测试来源当铜卡。已有ID拒绝草稿通道。初始预览不是正式等级或资格授予。

临时卡保存事实指纹、照片ID、构图、活动模板版本、私有令牌及15分钟期限；渲染请求标识防止旧响应覆盖新结果。确认及正式提交均核对证据，正式登记才原子写入球员、本人/监护关系和已确认构图。身份证、手机号与授权状态不回传到卡片预览描述中。
