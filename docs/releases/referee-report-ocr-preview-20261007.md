## 接口与页面

- 比赛详情、出场阵容：上传裁判表，支持 JPG/PNG、不超过 3 MB。
- `recognizeRefereeReport`：认证并验证赛事读取和共享模块权限；调用百度表格 V2 与高精度文字识别。按姓名列定位固定号码、首发、替补、身份、上下场、进球、黄红牌列；只读取“比赛结果”标签后的比分。原图保存为比赛证据，返回签名草稿；不修改比赛记录。
- 弹窗对照原图，选择正式赛事名单球员；未知符号及姓名不一致不自动确认。修改角色、分钟、队长、门将；换人可按分钟配对，歧义须选择双方。
- `confirmRefereeReport`：重新核验正式名单、赛事和身份；比分必须与有效进球记录一致；相同原图与事件避免重复录入。经签名的 `updateMatch.importPaperReport` 事务保存，检查事件版本；电子裁判记录接管/锁定不允许导入，已核定阵容不静默覆盖。导入不自动结束比赛或归档赛果。
- 共享工作人员需同时拥有 `event.matches`、`event.teams`、`event.results`。授权记录、成员关系未更改。

## 2026-10-07 上传请求超限修复

用户实测照片约703KB，Base64整图传入webLoginApi被CloudBase网关以EXCEED_MAX_PAYLOAD_SIZE拒绝。现复用uploadLargeFileViaCloud的48KB分块、超限降24KB上传，保留原图；识别HTTP请求只传fileId。prepareUpload先核验比赛与授权，返回已有match-reports/比赛ID目录。后端只接受本场目录云文件，下载后验证3MB上限及图片格式，再调用百度。复用了线上uploadFile既有赛事报表目录与分块权限，不更新该函数，不更改授权记录。上传进度可见，OCR重试复用已上传图片。

修复提交48c2553、09531b5已进入preview；整套预览上传375个文件，包含同期球队资料库与演示资料改动。后端从新下载的线上包差量更新；线上入口、主JS、MatchDetail分包HTTP200和SHA-256一致，webLoginApi回下载入口摘要匹配。尚未代替用户上传真实裁判表或写比赛记录，真实识别与保存仍待试用。

## 2026-10-08 固定栏位语义分析与错行修复

用户实测指出首发/替补、GK、中场、连续进球分钟及比分漏解析，客队前两名队员被跳过。本轮以用户原图向百度获取表格与带位置的文字、手写识别结果，未写比赛。确认原表格引擎将主队首行姓名并入表头、姓名与号码错行，客队序号首两行为空或合并，旧序号守卫导致漏人；比分各文本块按纵坐标排序打乱。现以号码单元格为行锚，独立定位姓名，按固定字段与原单元格位置分析标记；不再以序号是否为单个数字来过滤球员。位置结果与手写补识融合，首发√、替补○/O/0、GK和C解析。

这张实际OCR输出经新解析器得到主客各16人，客队高勇3号、王建军6号补回，比分3:0。只读核对该场状态scheduled、组别periodMode=halves、matchMinutes=30，故中场换人候选为30。单场冻结时长优先；历史无快照时提示复核当前配置，不反写时长。3528按35、28拆分候选，45分钟半场按45。原图OCR将某处连写数字读为3558，拆成35、58并保留原文核对提示，未强行改成用户泛例。肖军黄牌涂改位置两个识别引擎仍不能可靠识别为5，保留未知标记供人工填写；仅表格引擎认出的不可靠进球候选以?标识，不能直接确认保存。未把字迹未知写成0或正式事件。
