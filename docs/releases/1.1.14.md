# 1.1.14 按球员查看原表切片

日期：2026-10-15。用户要求在待核对球员处直接打开该球员的原表切片，对照号码、首发/替补及进球分钟完成确认。

## 使用方式

每个识别球员旁增加查看切片，弹层展示本队该球员整行及同一张表的表头，保留跨身份、换上/换下及进球栏的手写，不仅截取程序已识别的数字。切片默认放大并可左右滑动，点击图片用微信原生预览进一步放大；查看整表仍保留。弹层里直接选择本队球员、首发/替补及修改事件分钟，确认此行后返回剩余待核对名单，修改同步到原识别草稿。

看图和改候选不写比赛，也不会自动勾选已核对；整场仍沿用原仅保存阵容/保存赛果操作及服务端校验。没有位置的自由文本/人工新增行、原图失效或方向尺寸变化明确提示查看整表或重识别，不能用相邻姓名或列表序号猜切片位置。旧草稿没有完整行坐标，需重新识别。

## 实现范围

webLoginApi的refereeReportAnalysis按本队实际表格行生成reviewRegion和reviewHeaderRegion，包含姓名到红牌的整行；原事件局部复识别区域不变。refereeReportImage将增强图坐标按裁切偏移/缩放逆变换回上传图片并裁定边界。OCR输出analysisVersion为referee-report-analysis/6，imageQuality.regionCoordinateSpace明确为uploaded_image，原文件摘要和现有证据签名流程保持。

小程序refereeReportSlices使用当前上传的本地文件、2D Canvas及原生PNG导出生成切片，不新增公开图片URL或远程切片服务。合成图仅排列真实表头与真实行，中间留白分隔，不补笔迹。图片尺寸须与识别文件吻合。当前照片内按稳定行key缓存，重识别/换图/取消清理；绘制串行，关闭、跨场、离开和迟到结果受请求代次保护。sourceRegion/markRegion仍是识别内部坐标，不供手机误当原图坐标使用。

PC/H5未修改；getMiniWorkspace沿用原结果转发，无须新部署；updateMatch及真实比赛数据未改动。保持同队正式球员稳定ID、权限、事件版本、签报锁定和原确认流程。
