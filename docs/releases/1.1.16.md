# 1.1.16 阵容首屏与球员卡加载、PC阵型一致性

日期：2026-10-16。针对手机卡在首发0/0和正在加载阵容、球员卡慢以及阵型与PC不一致的问题。

## 问题与改动

原页面先读比赛详情，再请求整队lineupCards；只有全部卡元数据返回才设置比赛人数、显示球场。每张可见卡又走lineupCardImage，重复读统计、模板和资料。手机另有硬编码阵型子集，按首发数组顺序放人；保存只传首发/替补ID，服务端丢弃formation及role。即使PC已有位置，重排数组或手机保存也会错位。

现在比赛详情随原授权名单并行返回lineupRules，球场、人数、号码和姓名先显示，卡图结果不阻塞排阵。删除详情中未用于返回的阵容快照读取，只读取当前对阵所需球队资料；名单侧的查询和补资料并行，单队读卡不再读取对手名单。没有人数配置时明确失败，不用0冒充实际人数。

卡图直接按可见球员调用既有统一成卡服务，去掉整队元数据前置请求；每个请求波次首批最多3张以减少首卡等待，后续最多6张、最多2批并发。替补席按可见范围逐步读取，页面内按本场/球队/请求代次及卡版本复用已加载结果，切回球队不重复生成已加载卡。底层仍无跨账号完成卡缓存，返回前仍校验权限、当前模板、卡库与资料版本；没有改等级算法或卡内排版，没有为提速回退到过期卡。

PC既有阵型目录提为shared/lineup统一源，sync-football-formations同步PC JSON、小程序JS目录和getMiniWorkspace部署副本，并支持--check。5/7/8/9/11人阵型ID、位置编号和坐标取同一份定义；手机竖屏只旋转并统一留边展示。按已保存role恢复人，不按数组顺序猜位置；改变阵型按共有位置保留人，失去对应位置的首发进入待排位，人数不丢失。

手机保存传lineupLayout，服务端验证阵型所属人数、位置和本队首发稳定ID的一一对应，写PC原formation/players.role/number结构。旧入口没有传战术信息时保留原有效阵型和已知位置。纸质裁判表确认只在首发稳定ID集合完全相同时保留已保存PC战术，不用纸表序号生成战术位置。只有首发名单、没有战术证据的历史记录列为首发待排位，不宣称已知道谁踢门将或后卫；没有自动改写这类真实比赛。
