# 球员占位、认领与正式登记 v2

2026-10-18。用户确认并要求实现：负责人可先占位；球员正式登记先查找本队已有档案，明确认领或新建，必填资料、号码判重、百度抠图并接统一球员卡。

## 最终流程

- 球员库保留“添加球员”“邀请入队”两个独立按钮。手动添加直接打开表单，姓名或联系手机号至少一项，生日可后补；只有一个保存操作。新占位始终待补资料，不能因为已有姓名/生日就被算成完整档案。
- 保存后进入该稳定playerId详情；“邀请补资料”生成指向此球员的服务号邀请，编辑资料与移出球队保留为独立操作。普通球队邀请不会误复用定向球员邀请。
- 服务号先验证手机号，再用完整姓名或身份证查找本队有效档案；只在缺teamId时兼容指向本队稳定ID的历史teamCode，明确属于其他球队的记录不会借旧teamCode进入候选或号码库；候选仅返回姓名、出生年、号码和脱敏身份证。由用户明确选择认领，都不是本人时明确新建，不按姓名/生日自动合并。
- 认领已有身份证须输入核对一致；档案已有有效联系手机号时须匹配验证账号。无身份证/手机号的历史档案转负责人核对；新手动占位可凭负责人针对该playerId发出的定向邀请办理。已由其他账号关联的档案不能被静默换绑。
- 正式登记的姓名、身份证号、号码、位置、身高、体重、形象照必填；身份证校验位及出生日期核对，不宣称权威实名或人证核验。已有资料带入，照片可保留或更换。
- 服务端完整读取本队有效号码库，归档/删除排除，021与21按同一数字比较，认领仅排除所选档案自身。球队revision事务控制同一登记入口的并发号码竞争，冲突返回具体号码且保留表单。提交选择、重复提交和版本变化均校验。
- 照片复用baiduRemoveBg。原照保留，非透明图先缩至800像素画布再分割，避免高分辨率foreground超过既有4MB响应限制；有效透明旧照直接复用。只有会话内处理成功的portraitId可提交。更换失败恢复原预览，不把未处理原图冒充成功。
- 资料提交后直接预览统一球员卡，等级取数据中心，模板取已发布版本。只调整人像大小与位置，保存核对账号归属、卡片修订和模板版本；模板/数据暂不可用明确可重试，不补零或默认发铜卡。普通入队邀请可继续登记其他球员；定向补资料只处理指定档案。
- 认领保留已有orgId租户归属及原playerId；不按邀请机构覆盖旧档案归属。
- 延续parent_portraits及parent_profile_submissions的本人/监护关系，个人端可沿原链路读取。生日不足18岁仍由监护人办理。日常球员库、赛事名单、比赛阵容与赛果保持独立；没有修改历史快照或授予赛事资格。
