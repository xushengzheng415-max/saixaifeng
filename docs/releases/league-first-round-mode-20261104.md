# 联赛首轮对阵方式 2026-11-04

状态：隔离算法及实际浏览器链路验证通过，待发布。

问题：PC联赛抽签没有相邻签位/首尾配对选择，且QuickHybridConsole用首尾轮转、实际后端默认用相邻签位，预览与实际赛程可能不一致。

实现：首轮对阵可选adjacent（1对2、3对4）或head_tail（1对末位、2对倒数第二位）；后续轮次按同一圆桌规则轮转。模式随tournament_league_tables联赛抽签草稿保存、重开恢复、结果及投屏展示，预览/正式对阵/排期共用pairingTemplates函数；旧数据缺字段默认adjacent，保持原后端规则，单/双循环与奇数轮空一并校验。当前入口QuickHybridConsole只在联赛页提供选择，不改其他赛制规则。已确认联赛锁定模式与重写入口，后端现有对阵签名冲突保护保留，不自动重排已有比赛。投屏载荷转换普通JSON快照，修复Vue响应式对象不能被BroadcastChannel克隆的问题。

验证：2至32队×两种模式×单/双循环，检查完整对阵数量、无同轮重复、无重复交锋、正确轮空与回程主客互换；UI预览逐场等于真实confirmedPairings输出。实际8队浏览器验证默认1对2、切换1对8、28场、保存/重开恢复、已确认禁止覆盖；所有业务请求为本地桩，不操作真实抽签。原命名赛事模板、小组交叉晋级及对阵来源解析回归通过。

发布：generateSchedule以最新在线包差量3个业务文件，显式随包原依赖/关闭在线重装，保留运行时、内存、超时、权限与环境变量；不升级运行时，不发布小程序/H5。正式/测试PC保持同源，PC源码身份登记补上直接复用的对阵模块。读回待填。
