## 模型配置

- 去掉混元 3.5、Seedream 5.0 Flash 的硬编码隐藏；缺省配置仍只开启 Seedream 4.5，不自动开其他模型，也未代用户修改数据库中的启用/默认设置。
- 平台设置「启用 → 设为默认 → 保存配置」后，由统一 `aiPortraitDemo` 读取。客户端恢复焦点与每次生成前刷新配置；用户已明确选定且仍有效的模型可保留。
- 自选开启：请求按客户当前选择调用；自选关闭：服务端按后台默认执行，不能靠提交其他已知模型绕过。下架/未开通/无效模型拒绝，不静默换成另一模型；默认模型不可用则明确失败。配置读取失败关闭出图，避免退回错误的默认模型。
- 未更改模型提示词、凭据和运行配置。Seedream 4.5/5.0 Flash/混元调用路径保持原接入；本轮对三种分发完成离线测试，不据此声称三家真实生图都已重测。

## 鉴权、会话与费用

- `platformOwner.createAiPortraitToolSession` 先执行现有 `requireOwner`，再创建 15 分钟随机工具会话；仅 SHA-256 摘要写入既有私有 `auth_sessions`，文档前缀 `portrait_tool_`、`principalType:portrait_tool`、独立 scope，不是自然人/平台登录会话。验证失败关闭访问。
- `aiPortraitDemo` 每次后台工具请求查验工具会话有效期、scope、操作人及 active；不接受从 HTTP 或普通云函数调用直接创建会话。跨域 iframe 消息同时校验发送来源窗口与精确域名；短时令牌只在内存和指定消息中传递，不写 URL、存储或日志。
- 高清上传准备/取消、带高清参考凭证和透明输出的新工具链路均拒绝非后台会话；已有客户业务接口保持原授权范围。本工具不调用蜂蜜钱包、扣费或订单逻辑，模型服务商 API 用量仍按既有日志记录。
- `platformOwner` 从刚下载的生产包差量增加一个 action，保留其余代码与依赖；`aiPortraitDemo` 在同期最新源码上更新。未部署 webLoginApi，未改函数配置/凭据，未写球队/球员/比赛或钱包数据。
