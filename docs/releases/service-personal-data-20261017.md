# 服务号球员与裁判数据入口（2026-10-17）

## 用户确认与故障原因

用户确认H5主要服务球员和裁判，需要本人比赛数据、本人执裁数据和可点击的比赛记录，而不是球队/主办赛事的静态资料目录。更新PRODUCT_RULES及ADR，替代同日个人目录首版布局。

只读核对用户反馈同名档案后，确认其中有已归档旧记录。首版personal personFields没有投影status，后续过滤读不到归档标记，因此旧记录被再次显示。现将status/isDeleted及来源字段加入最小投影，先排除归档、删除、测试档案再建立身份列表；历史记录保留，没有删除、按姓名去重或合并真实球员。不同稳定ID的有效同名档案仍保持独立。

## 当前行为与数据边界

- `servicePrivateOverview`仅发现账号已关联的本人/监护球员和本人有效裁判身份，不再聚合球队、主办赛事目录；没有这两类身份时给出既有邀请/裁判任务入口。
- `servicePrivatePlayerData`每次由有效服务号会话重新校验自然人账号与目标球员的playerUserId/linkedUserId/guardianUserId关系，并重新检查档案状态及来源。独立授权后调用原data-center/service.query的已授权生涯能力，只返回该球员的正式指标、完整度、版本、实际关联比赛及本人事件，不返回其他球员、整份统计数据、排名或私有字段。未知指标保留null，客户端显示破折号；明确0保留。
- `servicePrivateRefereeData`只从本人经已验证手机号对应的有效裁判ID读取match_referees。排除撤销、拒绝、待认领等未确认关系，按实际matchId去重并列出岗位；历史已接受/批准/完成指派可只读查看，不授予现场写权限。执裁摘要是唯一有效指派比赛的总数/已结束/未结束工作量，不当作竞技积分或裁判评分。过滤比赛及主客队、赛事的测试来源。线上不存在referee_library，本入口不创建或依赖它。
- H5新增`service-personal.js`及独立`service-private.css`。同时拥有两类关系时显示球员数据/执裁数据页签；多球员按稳定ID切换。比赛可点击进入比分、时间、场地及本人事件/执裁岗位，支持返回，裁判任务沿用既有工作台链接。切换代次隔离迟到响应；不新增机构后台。
- 不写真实球队/球员、名单、比赛、事件或成绩；不改卡片、资格、等级、历史归属或指标算法，不按姓名继承已归档档案的生涯事实。自然人绑定、手机号唯一性、撤销绑定和原OAuth规则保持。
