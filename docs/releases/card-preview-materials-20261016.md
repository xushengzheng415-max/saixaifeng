# 发放预览素材读取修复（2026-10-16）

## 现场与证据

用户截图：立洋杯发放预览已加载24/304人，前14人报同一条“球员卡素材读取失败”，后续卡片可显示。

以截图涉及球员及其稳定球队ID只读检查：照片、队徽、当前铜卡背景与遮罩均存在，实际PNG返回200，背景/遮罩300×430，跨域头允许平台域名。采用同一现有素材和已发布布局，在浏览器平台来源下重绘14名受影响球员，14/14成功。没有重新上传或修改球员/球队/模板。

截图未保留历史HTTP状态，不据此认定原照片损坏或某次限流已经得到证实。明确发现的链路问题是：服务端24张同时重复请求共用素材地址；浏览器整页并行绘制且图片没有共享读取或有限重试；不同素材错误都报同一句；“重试预览”会清空所有成功卡片。

## 修复

- playerCardPreviewAssets为单次已授权请求合并、复用文件地址查询，失败仅对缺失项重试一次，不跨用户或跨会话缓存签名地址。每个查询批次不超过50项。
- issuePreviews按4张并发处理，保留原顺序和原服务端范围、等级、样式及撤销校验。descriptor逐项报告背景、遮罩、照片、队徽地址失败；必需素材未就绪不伪造可发状态。
- 统一draw模块同批共享图片读取，最多2张同时绘制；图片有限重试、超时和失败缓存清理。报告具体cardAsset/cardErrorCode，锁定/无权/撤销状态不能因绘图成功而放开。未改裁剪、遮罩黑白语义、文字布局或300×430坐标。
- 平台重试只请求已加载失败球员，保留成功图片和顺序。补成功后继续加载其余所选名单；模板版本变化要求整批重新预览，旧版本不能混入确认发放。未全部加载成功仍禁止确认发放。
- 失败卡位保持同样比例，区分加载数、成功数及失败数。

## 验证

- 24张浏览器样本共用背景/遮罩/队徽各只读一次；注入照片首次失败后恢复；持续失败明确指出球员照片；失败缓存清除后可重试，锁定状态保持。
- 实际平台界面隔离测试：3人预览中1张失败时确认发放禁用；重试仅提交该1人ID，另2张成功图片逐字节保留；全部成功后原预览/确认/幂等发放链路通过。未写生产发放记录。
- 真实14名球员素材只读浏览器重绘通过。原动态模板、原生绘制、遮罩/隐私投影、按需导出、三端模块同步及独立平台构建通过；积分明细与数据治理回归通过。
- 最新线上web包仅变playerCardDynamic、playerCardWorkflows与新增playerCardPreviewAssets。实际包语法/依赖及裁判表防回退检查通过；回下载比对其余运行文件不变，npm生成锁元数据除外。保留当前运行配置和同期裁判修复。
