# 1.1.19 首页排除虚拟球队与删除本人空球队

日期：2026-10-16。用户指出虚拟球队不应进入首页，并明确选择永久删除自己名下的空球队。

## 修复和规则

只读核验蓝湾逐风、彩虹飞鱼、银湾风暴、北辰竞技均有synthetic=true、source=ai_fixture及来源批次。上一版只核对访问关系，漏掉来源筛选。homeEntries现直接调用统一statistics.synthetic过滤球队、机构及共享赛事，不按名称判断；机构赛事投影包含来源字段，sharedEvents透传synthetic。homeEntriesVersion=home-entries/2阻止旧未筛选缓存再显示，不把旧缓存当完整空结果。没有删除虚拟数据库记录。

入口为球队→自己的球队→球队资料→底部删除空球队，仅主账号显示。空队须没有球员（含旧teamCode）、历史归属/转会、报名参赛、正式名单、阵容、比赛事件和导入草稿，非零摘要也拒绝。有记录时禁用并提示原因。teamDeletionInfo检查后，用户确认具体球队的不可恢复提示，再调用deleteEmptyTeam；服务端重新检查稳定团队/空间、本人权属、名称和完整资料摘要。当前owner字段须一致属于本人，旧owner角色不能压过新权属；creatorId、管理员及赛事共享不授予删除权，force无效。

关联查询失败阻断，明确集合不存在才能跳过。确认后重查关联，doc事务内回读球队并CAS完整摘要，同时写最小审计和移除球队文档，不级联删除球员、账号或历史。按[CloudBase事务说明](https://docs.cloudbase.net/database/transaction)，事务不支持where，本实现关联范围检查在事务外，不能称为跨集合范围锁；球队文档及审计原子提交。已有成员/邀请引用随球队不存在失效，不通过旧引用重建球队。未接入或改写PC旧force级联入口。成功清空间/选中球队并重进球队页，无空间时显示可创建空状态，不更换登录协议。
