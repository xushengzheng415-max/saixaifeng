# 赛小蜂球员编号规则

> 适用：三端统一（小程序 / PC端 / 赛事中心）
> 数据库集合：`players` → 字段 `playerId`

---

## 编号格式

```
[球队编号9位][序号3位][类型1位] = 共13位

示例:
  226E00112 001 C
  └─球队编号─┘ └序┘ └类型┘
```

| 段位 | 长度 | 说明 | 示例 |
|------|------|------|------|
| 球队编号 | 9位 | 取自 `teams.teamCode` | `226E00112` |
| 序号 | 3位 | 该球队下自增编号，从 001 开始 | `001` |
| 类型标识 | 1位 | 人员身份类型 | `C` |

> ⚠️ **来源（source）不在编号内**，来源信息存储在独立的 `source` 字段中。

---

## 类型标识对照表

| 标识 | 含义 | 说明 |
|------|------|------|
| `A` | 教练 (Coach) | 教练组成员 |
| `B` | 工作人员 (Staff) | 队医、领队、后勤等 |
| `C` | 球员 (Player) | 普通球员 |
| `X` | 多身份 (Multi-role) | 可兼球员+教练/工作人员 |

## 生成逻辑（伪代码）

```javascript
function generatePlayerId(teamCode, personType, overrideSeq) {
  // 1. 如果手动指定序号（批量导入用）
  if (overrideSeq > 0) {
    return teamCode + pad(overrideSeq, 3) + personType
  }

  // 2. 查该球队下已有球员的最大序号
  let maxSeq = 0
  for (const p of players) {
    if (p.playerId?.startsWith(teamCode)) {
      const seq = parseInt(p.playerId.substr(9, 3))  // 第10-12位
      if (seq > maxSeq) maxSeq = seq
    }
  }

  // 3. 序号+1
  return teamCode + pad(maxSeq + 1, 3) + personType
}
```

---

## 关键规则

1. **序号按球队独立递增** — 不同球队的序号互不影响
2. **类型互不影响序号** — A/B/C 共享同一序号空间
3. **删除球员后序号不复用** — 避免历史记录混淆
4. **来源用 `source` 字段存储** — 不在 playerId 里
5. **三端统一一个函数** — 小程序/PC/赛事中心用同一套逻辑
