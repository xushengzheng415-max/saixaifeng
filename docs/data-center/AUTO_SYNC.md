# 数据规范自动同步

用户于 2026-09-29 明确要求自动同步 Obsidian，并将统一标准作为以后数据功能的默认执行要求。

## 默认开发流程

凡涉及球队、球员、名单、比赛事件、统计、榜单、导入和导出的修改，先读取 README、CONTRACT、INTEGRATION 与现行产品规则，沿用稳定身份、历史归属、指标口径、权限、完整度和版本。

完成改动后更新有证据的规范、入口登记和验收状态，执行：

```text
node tools/finish-data-change.mjs
```

此命令检查共享统计模块一致性、业务场景、治理规则和镜像状态；只更新项目规范，等待每日定时同步，不在每次开发后额外同步。失败必须明确报告；不能跳过检查声称已通过。

- 目标：`E:\Documents\LLM-Wiki-Knowledge-Base\01_Raw\01_赛小蜂足球\小程序与PC\数据中心\`。

- 单向同步：正式项目规范 → Obsidian 镜像。不会把 Obsidian 的未审核改动自动写回代码或产品规则。
- 本机任务：`SXF Football Data Knowledge Sync`，每天北京时间 09:10 执行一次，检测文件哈希，变化后备份、同步并逐字节校验；无变化不产生重复变更日志。同一天不重复执行定时同步。
- 镜像被手工修改时保留修改并报告冲突，不强行覆盖。来源缺失或读取失败时保留已有镜像，不自动删除。
- 本地状态：`.local-data-center-sync/state.json`、`daily.json` 和错误记录；旧 watcher 已停用。启动、停止和健康状态应以现场回读为准。

检查镜像：`node tools/sync-obsidian-data-center.mjs --check`。

## 规则巡检

Codex 已建立当前聊天的每日 09:00 巡检“足球数据规范与知识库同步”。它每日审核一次同步状态及数据变更是否沿用基准，更新有证据的规范后交给 09:10 的本机任务同步。审核任务不额外执行同步；只在失败、冲突、统计缺口或需要用户决定时通知。

每日同步需要本机开机并登录；每日审核还需要 Codex 应用运行。错过本机同步时间时恢复后补一次，当天不重复同步。

自动同步技术规范不等于自动同步生产球队/球员数据库，也不等于代码推送、合并 main、云函数部署或生产迁移。既有代码实现的推送和正式上线授权仍需分别处理。

默认执行标准可以减少遗漏；自动化不能替代真实业务验收。新的业务口径、权限冲突、无法证实的历史身份合并和正式发布仍须按当前用户指令处理。
