# 球队大名单海报定版规范

状态：**产品负责人已确认，2026-10-17定版。**

视觉、结构与交互基准：**1.1.39**。用户明确：“定版！以后的球队大名单就是这个逻辑走！”

后续球队大名单海报默认复用本规范，不自行换风格、移动分区、重画卡面或改排序。球队、赛事及组别信息随真实对象变化；若用户另有明确要求，再更新本规范与决策记录。当前已接入小程序；PC/H5今后接入或重做时遵循本规范，不代表现有PC旧海报已同步上线。

## 定版结构

1. **球场表头**：绿色球场背景，赛事LOGO与赛事名；前景完整队徽和队名、组别组成对齐单元。
2. **背景队徽**：同一球队队徽独立放大，以18%不透明度融入表头背景，能看到轮廓；裁切限定在表头，不覆盖人员区。
3. **居中标题**：“球队大名单”独立整行居中。人数是右侧次要单行信息，不能挤偏标题或恢复巨型数字。
4. **教练与工作人员**：位于球员卡阵上方，保留真实姓名和职务；有已授权卡片时复用本人完整卡，无卡时仍显示真实头像。缺照片才提示待补充，不出现测试占位人员。
5. **参赛球员**：三列完整球员卡，透明背景、轻微整体错位，保持300:430比例；不另加白底、圆角底板或圆形人物裁切，不重排卡内人物、文字、队徽、号码或等级。
6. **页尾**：赛小蜂足球标识文字、分页信息及必要球队信息，保持克制。

## 排序与人员关系

- 卡片按后台当前展示卡种 **金 → 银 → 铜** 排列；同卡种保留原名单顺序，未知项放最后。工作人员卡片沿用同一规则，无卡人员保留原登记信息。
- 展示卡种取统一服务返回的cardTypeId，明确tier只作兼容；不分析图片颜色、文件名或背景地址，不改写竞技等级和积分。
- 工作人员与球员只通过已登记稳定球员ID关联，不按姓名、号码猜测。冲突不选第一条，无卡不自动发铜卡或新建球员档案。
- 兼球员的教练、领队、队医可同时出现在工作人员区和本届球员区，但名单人数仍按原快照去重计算，不重复计数。

## 名单与状态

- 入口：球队管理者 → 对应球队的参赛赛事 → 正式名单 → **生成海报**。
- 仅使用该球队、本届赛事、当前组别的名单快照；不把长期球员库全员当本届名单。
- 已审核/确认/锁定的海报不重复显示“正式名单”字样；草稿、待审核、退回仍保留真实状态提示。不因生成海报而改变审核、资格或历史快照。
- 加载进度、错误和重试放在海报操作界面。明确缺卡可使用已授权照片/姓名并标识；加载失败或无权不能冒充缺卡，不能带着未完成的加载状态导出。
- 每张最多24名球员、12名工作人员；超出分页，不静默截断。每张都保留所属球队、赛事/组别与页码。

## 预览与导出

预览和保存采用同一信息层级、素材、顺序及透明度。导出宽1200px，高度随当页人数计算，完整卡和人物等比显示。保存相册、重复点击、网络失败、重试及离页/换账号后的迟到响应沿用既有保护。

固定的现行表头参数：背景队徽opacity/globalAlpha=0.18，独立620rpx放大图层；前景队徽88rpx、队名32rpx，人数22rpx次要单行。标题独立居中，不与人数共占偏斜的横排。设备适配可等比调整周边布局，不改变卡片内部。

## 实现与验收入口

- 小程序入口/状态/预览保存：`miniprogram/pages/team/roster-poster/roster-poster.*`。
- 名单成员、稳定排序与分页：`miniprogram/utils/roster-card-poster.js`。
- 海报合成：`miniprogram/utils/roster-poster-paint.js`；完整卡读取：`miniprogram/utils/player-card.js`。
- 原接口：officialRoster、teamMembers、playerCardBatchRead，保持原工作空间、球队、赛事及组别授权。
- 工作人员稳定关联投影：`cloudfunctions/getMiniWorkspace/teamMemberView.cjs`；不得借展示调整扩展权限。
- 回归：`tools/test-mini-roster-card-poster.cjs`、`tools/test-mini-roster-staff-cards.cjs`。
- 验收必须加载实际app.wxss，避免通用.card白底/内外距再次污染海报；核对真实透明成卡、无卡头像、排序、审核状态、分页及实际导出PNG。
