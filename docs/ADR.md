# 赛小蜂足球决策记录

| 日期 | 决策 | 结论 |
|---|---|---|

| 2026-07-29 | 端口分工 | PC 是完整后台，小程序服务机构协作，服务号服务个人任务，公开 H5 服务传播 |
| 2026-07-29 | 免费/付费边界 | 赛事协作与球队基础管理免费，俱乐部日常经营能力付费 |
| 2026-07-29 | 赛事收费单位 | 专业版按 `Division` 竞赛组别收费，不按整届赛事或单场比赛收费 |
| 2026-07-29 | 版本价值分层 | 简易版是球队级管理，专业版是正式球员级、结构化、可追溯数据 |
| 2026-07-29 | 版本锁定 | 明确确认竞赛方案后锁定；锁定前简易版可无损升级专业版 |
| 2026-07-29 | 权限框架 | 使用预设岗位加可调整权限，权限来自机构和业务关系 |
| 2026-07-29 | 小程序信息架构 | 当前机构是工作空间；底部固定为首页、赛事、球队、青训、我的，三个业务中心独立承载 |
| 2026-07-30 | 比赛现场执行边界 | 主办方 PC 只做赛前配置、赛中只读监控和赛后复核归档；球队小程序提交单场阵容，获授权裁判通过服务号/H5 执行现场核验、事件记录、电子记录和签字 |
| 2026-07-30 | 赛后纠错责任 | 正常流程只能通过或退回裁判限定修正并重新签字；主办方异常纠错必须记录原因、处理人、前后值和时间 |
| 2026-07-31 | 小程序首页身份化 | 登录后按赛事负责人、球队教练或青训教练身份直接进入对应首页；顶部只显示不可点击的固定身份文字，身份切换统一放在“我的” |
| 2026-07-30 | 主办方移动端赛中边界 | 主办方小程序赛中只读，可联系裁判、提交异常和跟踪处理，但不能修改比分、阵容、事件、电子记录或签字 |
| 2026-07-31 | 服务号入口简化 | 关注后自动回复球队负责人、裁判员和球员家长三个办理入口；球队跳小程序，裁判与家长进对应 H5，主办方不进入服务号工作台 |
| 2026-07-31 | 小程序首次进入分流 | 已绑定机构的账号按最近使用的已授权身份直接进入；无业务关系账号先选择场景，首次创建或认领后绑定唯一机构 |
| 2026-07-31 | 首次创建场景边界 | 球队保持三步极简创建；赛事支持手机基础创建并引导复杂配置到 PC；青训先展示付费权益与开户状态，只有后台已开户机构才能创建 |
| 2026-07-31 | 青训功能演示边界 | 未开户用户可进入独立示例数据演示；演示不创建机构、不保存业务记录、不产生费用，也不授予正式权限 |
| 2026-07-31 | 小程序机构链路收口 | 删除机构选择和机构切换；取消临时球队工作空间；“我的”只切换同一机构内身份；访问受限仅作为异常状态 |
| 2026-08-01 | 组别纪律规则 | 简易版与专业版都配置红黄牌累计、停赛和清零规则；专业版事件关联正式名单并自动执行停赛，简易版允许人工文字事件 |
| 2026-08-01 | 专业版竞赛规程 | 专业版规则定版时自动生成带版本号的《竞赛规程》并支持预览、导出；简易版只保留规则摘要，不生成正式规程 |
| 2026-08-01 | 专业版球队认领 | 主办方快速添加专业版球队时负责人和联系电话必填；球队必须在小程序完成认领与参赛确认，之后才能提交赛事参赛名单 |
| 2026-08-01 | 专业版球员资料责任 | 专业版球队自行维护球员库和赛事参赛名单，可邀请家长补充资料；主办方不得逐个代录或批量导入，若不需要球员级资料应选择简易版 |
| 2026-08-01 | 球队邀请认领去重 | 主办方快速添加只形成待认领参赛占位；负责人打开邀请后选择已有球队加入或认领预设球队，系统不自动合并冲突数据 |
| 2026-08-01 | 待认领邀请分享边界 | PC端不直接向指定微信发送小程序卡片；待认领阶段只生成链接和小程序码，主办方自行转发，认领后才进入资料完善通知 |
| 2026-08-01 | 球队创建与邀请三路径 | 无赛事关系只自主建队；受邀参赛由邀请深链明确分为“新建球队参赛”和“接收预建参赛队伍”；默认球队中心取消搜索认领入口，冲突仅作为邀请接收异常分支 |
| 2026-08-02 | 球队详情信息架构 | 球队中心卡片直接进入球队详情且不保留快捷菜单；球队详情作为二级入口，下设球队资料、球队成员、球队球员库、参赛管理和历史参赛记录五个三级页面，参赛管理继续进入球队视角赛事详情 |
| 2026-08-02 | 专业版名单异常入口 | 主办方名单异常处理并入专业版球队管理，固定由参赛名单页的异常数量或处理按钮进入，并提供返回参赛名单；不再作为“跨端闭环看板”的独立入口 |
| 2026-08-02 | 专业版球队管理二级菜单 | 专业版球队管理的列表、详情和弹窗页统一固定为“参赛球队、加入申请、参赛名单、名单异常、名单变更”五项菜单；位置、尺寸、间距和选中样式使用同一套视觉基准 |

## 已被替代的旧规则

| 旧规则 | 状态 | 替代结论 |
|---|---|---|
| 足球赛事和青训产品使用 `saixiaofeng.com` | 已废弃 | 赛小蜂足球独立使用 `www.sxffootball.cn` |
| 当前唯一登录身份是主办方 | 已废弃 | 自然人账号通过机构、球队和赛事关系获得权限 |
| 历史账号统一归一为 `organizer` | 已废弃 | 保留单机构内多岗位和多身份授权；兼容字段等待正式迁移 |
| PC 与小程序所有功能完全对等 | 已废弃 | 数据与规则一致，页面能力按使用场景分工 |
| 小程序只服务主办方 | 已废弃 | 小程序服务主办机构及俱乐部/球队机构 |
| 服务号仅提供球队比分只读查询 | 已废弃 | 服务号承接裁判等个人身份的通知与任务 |
| 裁判现场操作以小程序为唯一入口 | 已废弃 | 裁判业务规划转移到服务号入口 |
| 用固定手机号决定角色或是否登录 | 已废弃 | 权限只依据账号状态、机构成员关系和业务授权 |
| 赛事中心使用独立账号和独立登录 | 已废弃 | 统一使用平台登录和可信权限校验 |
| 小程序底部使用工作台、日程、待办、数据、我的 | 已废弃 | 使用首页、赛事、球队、青训、我的；首页按当前业务场景展示 |
| 赛事与青训日程、待办和数据默认跨模块聚合 | 已废弃 | 赛事与青训独立展示、独立授权和独立计费 |
| 多业务机构首页同时堆叠赛事、球队和青训摘要 | 已废弃 | 首页按当前身份展示，一次只展示一个身份的工作内容 |
| 首页顶部使用“赛事主办 / 球队协作 / 青训经营”标签切换场景 | 已废弃 | 顶部只显示不可点击的当前身份文字，身份切换统一进入“我的” |
| 主办方小程序可在赛中快速录入或应急修改比赛数据 | 已废弃 | 主办方移动端赛中只读，现场数据仅由获授权裁判端写入 |
| 微信端使用“进入赛事服务 → 我的赛事工作台”统一分发主办方、球队和裁判 | 已废弃 | 服务号关注后按办理事项直接分流；主办方走 PC/小程序，球队跳小程序，裁判与家长进入对应 H5 |
| 小程序微信授权后统一进入“确认球队认领与参赛” | 已废弃 | 已有业务关系自动进入对应场景；无业务关系才进入三步极简创建，邀请深链确认另行设计 |
| 青训教务与球队、赛事一样可直接免费创建 | 已废弃 | 青训为独立付费服务，必须先展示权益和开户状态，仅后台已开户机构可创建 |
| 一个自然人账号可加入多个机构并在小程序切换 | 已废弃 | 当前阶段一个小程序账号只绑定一个机构；机构可有多校区和多身份 |
| “选择工作空间 → 切换机构 → 临时球队协作空间 → 工作空间访问受限”是一条正常连续链路 | 已废弃 | 删除机构选择、机构切换和临时空间；访问受限只作为异常状态 |
| 未认领球队先进入临时球队协作空间 | 已废弃 | 主办方可先建立待认领参赛档案，但球队负责人完成创建或认领后才能进入正式球队工作空间 |
| 专业版允许主办方逐个代录或Excel批量导入球队球员 | 已废弃 | 专业版球员建档与参赛名单由球队负责，主办方只审核进度与处理异常；球队可邀请家长补充资料 |
| 主办方快速添加即直接创建一支长期球队 | 已废弃 | 只创建待认领参赛占位；负责人优先选择自己的已有球队加入，没有球队时才用预设资料建立长期球队 |
| 无球队状态同时提供“创建球队”和“搜索并认领球队” | 已废弃 | 无赛事关系只提供创建球队；认领或接收只能由主办方赛事邀请深链触发 |

## 尚未形成 ADR 的事项

以下内容仍待确认，不能作为当前决策：

- 专业版价格、优惠、退款、发票、支付渠道和试用期；
- 机构成员关系的最终数据库集合与迁移步骤；
- 球员、监护人及其他个人身份的完整页面和任务清单；
- 青训经营 SaaS 的套餐和计费方式。
