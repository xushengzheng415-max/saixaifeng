## 正式菜单

| 一级菜单 | 类型 | 正式落点 | 边界 |
|---|---|---|---|
| 赛事中心 | 网页 | `https://www.sxffootball.cn/admin/#/portal/home` | 公开赛事、赛程、比分和排名，无需登录 |
| 裁判任务 | 网页 | `https://www.sxffootball.cn/service-account-h5/?entry=workbench` | 只承接已获授权裁判的个人比赛任务 |
| 我的 | 网页 | `https://www.sxffootball.cn/service-account-h5/me.html` | 登录后按真实关系查看孩子、执裁、球队和赛事私有数据 |

接口发布载荷保存在 `service-account-h5/wechat-menu.json`。

## 产品边界

- 菜单按用户意图组织，不按主办方、教练、裁判、家长等永久身份拆分。
- “我的”是手机号自然人账号的私有数据入口，不是观众专页，也不是单一角色工作台。
- 监护人查看自己孩子的数据，裁判查看本人执裁数据，球队负责人查看自己球队的数据，主办方查看自己赛事数据。
- 主办方、俱乐部和球队的管理、审批及配置继续使用微信小程序或 PC 管理后台；服务号以只读数据、通知和回流为主。
- 监护人和球员资料必须从球队发送的专属邀请进入。“我的”不允许搜索球员、查看整队名单或绕过邀请。
- `service-account-h5/` 历史根入口继续兼容裁判工作台；“我的”使用独立静态页，避免影响既有裁判和家长邀请深链。

## 发布与回读

公众号后台显示“开发者通过接口修改了菜单”属于正常状态。菜单应继续通过固定出口和公众号接口统一发布，不切换为后台手工菜单。

发布属于生产配置变更，必须在当前任务获得明确授权后执行。发布前后依次验证：

1. 三个正式 URL 均可在微信内打开；
2. “赛事”不触发登录；
3. “工作台”只进入裁判个人任务授权链路；
4. “我的”不展示机构私有数据，监护人入口仍要求专属邀请；
5. 从公众号接口读回菜单，并与 `wechat-menu.json` 逐项比对。

2026-09-05 已将 `me.html` 与 `service-menu.css` 作为独立文件安全部署并从正式域名逐字节读回；未上传同目录中尚未发布的其他 H5 改动。固定出口已增加受 HMAC 保护的菜单创建和读取动作，服务重启后本机及公网健康检查均为 HTTP 200。公众号菜单首次创建为“赛事 / 工作台 / 我的”；实际体验确认“工作台”会直接进入裁判绑定后，菜单名称收口为“赛事中心 / 裁判任务 / 我的”，不再使用宽泛名称误导普通关注者。
