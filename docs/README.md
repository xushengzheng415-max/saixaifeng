# 赛小蜂足球知识库导航

本目录是项目代码仓库内的正式共享知识库。开发人员和 Codex 在修改功能前，应先阅读与任务相关的当前规则和状态；新增功能完成后，同步更新对应文档。

## 权威顺序

1. 当前任务中用户的明确指令。
2. 根目录 `AGENTS.md` 的安全、数据和技术红线。
3. `PRODUCT_RULES.md` 中标记为已确认的产品规则。
4. `CURRENT_STATUS.md` 中的当前阶段和验证状态。
5. `ADR.md`、发布记录、专题文档和历史资料。

旧文档、历史截图和原型不能覆盖已确认的新规则。发现冲突时先报告，不自行选取对自己方便的版本。

## 核心文档

| 文档 | 用途 |
|---|---|
| `PRODUCT_RULES.md` | 产品定位、角色、权限、收费与数据归属等已确认规则 |
| `CURRENT_STATUS.md` | 当前进度、线上/本地状态和验证记录 |

## 专题资料

- `DATA_CENTER_STANDARD_PROPOSAL_2026-09-29.md`、`data-center/README.md`：用户已确认的数据统一规范，所有数据机制按此基准统计。

- `releases/`：版本发布记录。
- `tutorials/`：面向运营和使用人员的教程与配图。
- `audit/`：专项审计结果。
- `prototype-assets/`：原型来源、图标与可追溯设计资产。
- `tournament-center-prd.md`、`tournament-center-architecture.md`：赛事中心产品与架构资料；使用时仍须服从当前核心规则。

## 新文档放置规则

- 长期产品规则写入 `PRODUCT_RULES.md`，不要另建相互冲突的“最终版”。
- 技术或产品决策写入 `ADR.md`。
- 当前进度、部署与验收事实写入 `CURRENT_STATUS.md`。
- 版本说明写入 `releases/`。
- 教程放入 `tutorials/<topic>/`，截图必须使用虚构或去标识化数据。
- 临时分析、导出、构建产物和工作文件不得放入知识库。

## 未纳入仓库的本地资料

本机旧资料目录中包含历史规划、竞赛文件、球队名单、球员表格和个人照片。它们没有整体提交到代码仓库，原因包括：

- 球员名单、照片、联系方式等可能包含个人信息；
- 大量文件是历史版本，可能与当前产品规则冲突；
- 压缩包、原始 Excel 和重复截图不适合作为开发规范来源。

如确需共享其中某份资料，应先确认授权与有效版本，去除个人信息和凭据，再转成清晰的 Markdown 或受控附件，并在本索引登记。不得直接把整个本地资料目录复制进 Git。

## 敏感信息红线

知识库不得包含密码、验证码、Token、Secret、API Key、私钥、生产账号、数据库导出、身份证信息或未授权的真实用户资料。配置文档只记录变量名、责任人、配置位置和验收方法，真实值留在仓库外的安全系统中。
