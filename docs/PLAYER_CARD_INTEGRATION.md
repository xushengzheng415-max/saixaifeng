# 球员卡统一调用规范

状态：2026-09-30 产品负责人确认。适用于 PC、服务号 H5、小程序以及后续新页面。本规范约束调用方式；不表示尚未接入的页面或积分新规则已经上线。

## 唯一球员卡

- 球员卡是独立模块，不是页面装饰。卡面、人物、前景、号码、位置、姓名、球衣名、身高体重、国旗和队徽采用同一套正式规则。布局或素材变化从模块统一修改。
- PC 的正式组件是 `web-admin-vue/src/components/player/PlayerCard.vue`。PC 新页面直接引用，外层仅负责尺寸、位置和打开详情；不得复制组件内的卡面 DOM、样式或等级算法。
- 已保存成卡优先读取服务端返回的 `playerCardFileId` 对应限时 `cardUrl`。H5、小程序及公开页面只展示其被授权的成卡，不从头像、姓名、背景图在当前页面重画卡片。
- 没有已保存成卡、读取失败、无权读取是不同状态。显示普通球员信息或明确的失败状态，不用默认金卡、铜卡或虚构数据补齐，也不把资料缩略图标成“球员卡”。
- 制卡和再次编辑进入球员卡模块的正式流程；调用页只传稳定 `playerId`、必要的会话及返回位置。保存后的版本、模板和图片由模块负责，不在调用页自行写入。

## 数据与权限

- 等级、积分及换照片或背景权益由统一服务端结果决定。旧页面使用的按场次分级只属兼容实现，不得作为新入口的规则。测试比赛、测试球队、测试球员和来源不明数据不授予正式积分或等级。
- 卡片的照片和身份资料按本人、监护人、球队或公开授权范围读取。榜单公开字段不自动授予读取私有成卡的权限；需要公开卡片时先建立服务端公开授权与文件读取契约。
- 列表、详情、阵容、分享和导出应引用同一已保存版本。缩略展示只缩放成卡，不重新布局内部字段。

## 新入口验收

1. 核对调用页是否直接使用 PC 组件或已保存成卡 URL，且有无卡、加载、失败和无权状态。
2. 对比同一球员在 PC、H5、小程序的卡面、人物、资料和等级；同一已保存版本应一致。
3. 核对测试数据过滤、照片公开权限与服务端等级结果；不能靠客户端回退补齐。
4. 将入口、授权范围、数据来源、版本和实际部署状态登记到数据中心入口表。构建、Git 推送或文档同步不等于生产发布。

现状：PC 球员详情及阵容编辑已复用 `PlayerCard.vue`；H5 和小程序仍有自行绘制卡面的历史入口，须在后续页面改动中逐项核对正式成卡的读取、权限和缺失状态。本次仅确立知识库规则，未修改页面代码，不能宣称三端已统一或正式环境已切换。
