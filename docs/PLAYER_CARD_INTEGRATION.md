## 一套配置、一套生成、各页调用

球员卡是独立的完整套件，不是某个页面的组件样式。平台后台统一管理模板、字段、坐标和素材；统一球员卡模块读取获授权的球员资料及已发布模板，生成完整成卡；手机、平板、PC 的列表、详情、阵容、分享和导出只调用模块返回的成卡，不在各页面排列人物、文字或卡面图层。

```text
平台后台配置并发布模板
  → 球员卡模块读取模板版本、球员资料和服务端等级
  → 同一渲染器生成成卡并保存版本
  → 各页面按球员 ID 与授权范围读取、缩放和展示
```

- 后台配置的是**字段映射和呈现规则**，不改球员事实。至少覆盖人物形象照、球衣号码、位置、姓名、球衣名、身高、体重、国旗、队徽；每项可配置显示、坐标、尺寸及适用的文字样式和层级。字段只从受控字段表选择，不接受任意数据库字段或页面自传的文字替换身份资料。
- 首版模板素材采用一张 300 × 430 背景 PNG 和一张同尺寸黑白遮罩 PNG，不要求上传独立前景图。黑色直接裁掉人物（包括背景透明的卡外区域），白色透出人物，灰色按亮度与遮罩透明度渐隐一次；背景保持原图，两图共用像素坐标。画布尺寸、人物裁剪区域、字段布局及字体由同一个模板版本管理。后台最终预览必须调用与正式成卡相同的渲染器，不能另做一张近似的 CSS 预览。
- 平台负责人可修改文字颜色、字号、字重、坐标及国籍旗帜、队徽的尺寸和坐标；球员或依法有权的监护人仅调整其标准形象照的大小和位置。资料事实更正走原资料与审核流程，球员编辑页不开放文字模板排版修改。
- 球员卡模块提供统一的制卡、更新、读取和状态接口。调用页只传稳定球员 ID、业务上下文及授权会话；返回成卡地址、模板 ID、已发布模板版本、卡片数据版本、等级与加载状态。各端可封装调用适配器，但不得再实现卡面绘制或等级算法。
- 同一已发布卡片在手机、平板和 PC 上保持相同画布比例、字段位置、人物裁剪、图层、文字和内容；**各端只等比缩放整张卡**。不能因屏幕宽度重新排版、裁切卡面、替换局部图片或另设字号。周边的操作按钮与页面布局可适配设备，但不得改变卡片内部。
- 没有成卡、正在生成、生成失败、无权读取须分别呈现。普通球员资料缩略图不能标作正式球员卡；缺失或失败不能默认铜卡、金卡或零分。

## 卡种、获得规则与展示选择

- 基础铜、银、金卡与限定卡属于同一球员卡套件中的不同卡种。后台以稳定 `cardTypeId` 管理卡种、名称、素材、字段布局、适用对象、发布状态与版本；生日卡、冠军卡、金球卡是未来可配置卡种的例子，**目前不预设它们的具体获得条件或上线状态**。
- 每种限定卡的获得规则单独登记规则 ID、版本、生效范围和时间、授权对象、数据来源、核验条件及发放/撤销策略。服务端从已确认事实判断资格并留下证据与审计记录；页面不能按生日字符串、赛事名称、奖项文案或客户端标记自行发卡。规则只能使用受控条件和参数；新增事实类型须先扩展套件的规则执行器与数据契约，不能在某个页面写一次性判断。
- 球员获得的限定卡与其基础等级卡**并存**，不会自动替换或改变铜银金等级。球员或依法有权的监护人可从已拥有且可展示的卡中选择当前展示卡；选择结果按稳定球员 ID 保存在服务端，所有端口读取同一选择。无权、未获得、已失效或被撤销的卡不能仅凭客户端传入的卡种 ID 显示为已拥有；回退到有效基础卡时须给出明确状态。
- 限定卡的获得及展示资格与基础卡积分、100 分换照片/背景权益分别校验，不能用限定卡外观冒充金卡，也不能把已有背景切换权益自动当作限定卡发放资格。若规则修订会影响已发卡，须明确是否追溯、保留或撤销，并记录处理结果，不静默清除球员已获得的卡。

## 后台发布与自动更新

- 草稿与已发布模板分离。发布产生不可变版本；保存草稿不影响正在使用的成卡。
- **后台发布新布局后，所有受影响的已保存成卡自动更新。** 这同时适用于基础卡和限定卡。球员卡模块使用保留的标准形象照、裁剪参数、当前获核定资料、基础等级与限定卡拥有记录，批量重生成对应卡种与模板的成卡。新制作的卡也使用同一新版本。
- 发布采用待激活版本：先完成重生成和校验，再统一切换活动版本。切换前各页面继续读取上一完整版本；失败的卡进入可追踪的质量队列，阻止本次版本整体激活，并向后台显示数量与原因。不得让同一模板的一部分页面显示新版、另一部分显示旧版，也不得跳过失败卡宣称全部更新。
- 每张成卡记录 `playerId`、`cardTypeId`、`templateId`、`publishedVersion`、`cardDataVersion`、`renderVersion`、文件 ID、生成状态与时间；限定卡另记录获得规则版本与证据引用。旧图片和版本保留供审计与回滚；成功激活后读取接口只返回当前活动版本。球员资料、标准形象照、已授予等级或有效卡种发生变化时，也由该模块触发重生成和缓存失效。
- 历史卡若缺少可重生成的源图、裁剪或稳定球员 ID，须先完成有记录的迁移或修复，再激活新模板；不能仅拿旧成卡截图二次绘制，也不能按姓名猜测身份。

## 数据、权限与验收

- 等级、积分及换照片或背景权益取统一服务端结果。测试比赛、测试球队、测试球员及来源不明数据不授予正式积分或等级；调用页不得按年龄、场次或卡面颜色推断。
- 本人、监护人、球队及公开页面分别按服务端权限读取。公开榜单字段不自动授权公开私有成卡；需要公开展示时须有明确的公开范围和成卡读取接口。
- 验收同一球员在手机、平板、PC 的列表、详情、阵容及导出显示同一活动模板版本和成卡内容，卡片内部只发生等比缩放；检查无卡、生成中、失败、无权、模板发布失败、旧卡迁移、资料修订、等级变化、限定卡发放/撤销、跨端展示选择和回滚。发布记录须有受影响卡数、成功数、失败数、活动版本及实际线上回读。

## 页面调用与版本同步

- 页面传稳定 `playerId`、业务上下文和授权会话，由服务端读取受控资料与活动模板。读取结果应有 `status`、`cardUrl`、`cardTypeId`、`templateId`、`publishedVersion`、`cardDataVersion`、`renderVersion`，不能只传一张不知版本的背景图。
- 状态至少区分可用、无卡、生成中、失败和无权。成卡地址有效期、读取错误和模板发布进度由真实响应驱动。私有成卡的读取范围不能因为榜单公开而扩大。
- 页面重新进入、恢复可见或收到活动版本变化后重新读取；缓存键包含球员、卡种、模板版本、数据版本及授权范围。签名地址仅用于临时展示。已完成的发布更新在各端刷新后应读取同一活动成卡，实时推送能力未实现时不得宣称页面已即时刷新。
- 保存草稿只更新草稿与修订号；发布进入待激活任务，所有受影响卡验证成功并切换活动指针后才提示“已生效”。任务应可中断恢复，并核对与发布并发的新制卡和资料变化，不能遗漏卡片或激活旧资料版本。
- 代码与文档合入 `main` 使开发者共用同一合同；后台发布切换卡面活动版本。新增页面仍需完成一次授权接口接入与验收。后续功能变更在系统层实现，再由各已接入页面消费同一返回结果。


## 赛事与定向预装分类（2026-10-01）

本地候选分支 codex/player-card-preload 基于新卡发布修复版本 1b046eb4。编辑器增加全平台、球队、赛事、球员分类，定向范围绑定稳定对象 ID，金银铜分别配置。旧模板缺分类时兼容全平台。对象名称由服务端回读，不接受客户端名称作为关联依据。

用户已明确：预装是添加到球员 H5 卡库，与已有卡并存；不是替换基础卡。全平台／球队／赛事／球员预装模板均按模板 ID 保存独立活动状态和发布任务；同一对象可有多张同等级卡。旧未配置 preload 的基础模板保持原活动指针兼容。预装新卡不改 players.playerCardFileId；再次发布只更新该模板已制作的专属卡。已发布模板禁止改绑，须新建。

编辑器按具体对象名称＋稳定 ID 选择球队、赛事或球员。对象检索和发布管理仅限平台负责人。H5 listMyPlayerCards 对当前授权球员添加符合范围的已发布预装卡；赛事资格取最新正式名单 approved/locked，添加记录保留规则版本与名单快照证据。player_card_library 按球员＋模板去重，添加后的卡不因转队静默删除。卡级与换背景权益仍由统一积分服务核定。预装不是授予金卡等级。

本次仅本地实现与验证；未部署、未迁移生产记录。


H5 getMyPreloadedPlayerCard、previewMyPreloadedPlayerCard、saveMyPreloadedPlayerCard 独立读取／生成／保存专属卡，模板事实及文字样式来自服务端，不接受客户端姓名、卡级、成卡图片或源图替换。selectMyPlayerCard 只改 playerCardDisplayTemplateId，可显式选回基础卡；未主动选用时保持原展示卡。仅 H5 当前页已接入卡库与展示选择，其他端尚未读取新展示选择。最终预览、保存、再次发布使用同一 PNG 渲染器。布局新增纯色／两到三色渐变、方向、字体、斜体、字距、描边与阴影；旧布局补默认值并保持原纯色。

## 等级快照与卡面样式（2026-10-01，本地候选）

基础等级与升级进度统一从 playerCard 快照读取，页面不使用卡面色、savedTier、档案累计字段或局部赛事指标推导。已保存卡面／预装选择仍按渲染模块的活动模板、renderVersion 与数据版本读取；这些是图片版本，不能代替等级 snapshotRevision。金卡可按现有权限选择其他背景，因此卡面样式与真实等级是不同字段。此改动不重新生成图片、不改变历史授予或展示选择。

未知显示待核定与具体原因；接口未接入和请求失败单独提示。ready 的0分照常显示0和真实进度。缓存等级须按 playerId＋授权范围＋规则版本＋snapshotRevision 校验，图片缓存按原渲染合同管理；读取失败不得把旧等级缓存当作新核定结果。
