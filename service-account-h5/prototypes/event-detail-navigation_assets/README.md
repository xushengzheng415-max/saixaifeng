## 页面结构

保留赛事名称、状态、横幅、日期地点和固定底部导航。横幅下方放置四个等宽一级页签：赛程、分组、榜单、赛事信息。赛程按开赛时间排序，并提供全部、未开始、进行中、已完赛筛选；分组按竞赛组别和公开赛程中实际出现的小组归纳球队；榜单页内再分为积分榜、射手榜、红黄牌；赛事信息仅展示赛事日期、地点和公开状态。

## 交互与状态

- 赛程：保持当前场次点击进入比赛详情；各状态内按开赛时间升序。
- 分组：无可用小组字段时显示“联赛组”，按首次排赛顺序从上到下列出球队；A/B 等小组按正常组序各自显示为独立表格，表内按 1、2、3… 排列。
- 榜单：积分、射手、红黄牌为独立切换项；积分仅统计已结束的公开比赛，射手仅统计已公开进球，红黄牌仅统计已公开纪律事件。各项数据为空时显示真实空状态。
- 赛事信息：只读，不引入报名、直播、竞猜或写入操作。

## 数据字段

- 分组：`divisionName`、`round`、`homeName`、`awayName`、队徽。
- 积分：已结束比赛的双方队名、比分、场次、胜平负、进失球、净胜球、积分。
- 射手：按竞赛组别与小组分别排名，事件的 `type`、`playerName`、`playerNumber`、`teamName`，只累计 `goal` 和 `score`；优先显示已公开阵容内的 `portraitUrl`/`avatarUrl`，缺失时显示姓名首字。
- 红黄牌：事件的 `yellow_card`、`red_card`、球员、号码和球队，头像规则与射手榜一致。
- 赛事信息：名称、日期范围、地点、公开展示状态。

## 素材决策

截图仅用于布局与层级对照，所有文字、表格、分组和榜单均由真实公开数据和 CSS 渲染。沿用当前赛事横幅、真实队徽以及已验收的事件图标，不新增截图裁片或页面专属图标。

## 素材缺口

公开接口当前不返回主办方手工维护的独立小组表、积分规则版本、球员助攻和公平竞赛分。因此分组从已发布赛程的轮次/小组字段推导，积分采用足球常规 3/1/0 规则；仅当已公开阵容带有 `portraitUrl`/`avatarUrl` 时才显示球员头像，不读取或公开证件照、人脸核验照片或其他敏感文件。

## 开发边界

正式目的地为 `service-account-h5/tournament-center.js`、`tournament-center-event.css` 和后续补充样式。保持仅开封立洋杯的公开范围、真实数据只读与网页端零 SDK；不修改后台赛事状态、分组、赛程、赛果或球员资料。当前明确需求即为该素材包的批准依据，可以开始正式实现。
