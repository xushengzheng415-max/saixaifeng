# 赛事战报重设计原型拆解说明

源图：`E:\Documents\sxf-football\web-admin-vue\prototypes\tournament-match-report.png`  
尺寸：`1960 × 1110`（PC 赛事战报后台当前页面截图）

## 页面结构

当前 PC 页保留赛事结果中心的导航、日期筛选、主题选择、PNG 导出按钮和发布边界提示。主预览区改为“竖版战报画布”，画布高度由实际比赛场次和进球事件数量自然撑开。三款定板统一保留顶部赛事名称空位，标题使用比赛日期/比赛日，不写固定轮次。

战报内容提供两种模式：

1. **纯比分**：序号、主队、主队比分、客队比分、客队、竞赛组别/阶段。
2. **比分＋进球球员**：在同一比分条下展开主客队已确认进球球员与进球分钟；没有正式 goal 事件时不补写球员。该模式按内容自动拉长画布，不强行限制为 2:3，并使用更紧凑的球员行距保证底部页脚完整显示。

三种视觉主题使用同一数据结构：

- 绿色定板：扁平深绿纸张、细香槟线和低对比场地线；中央比分采用小切角八边形，避免深六边形两侧尖角瑕疵。
- 蓝色定板：扁平深蓝纸张、钴蓝切角比分桥和大留白。
- 白色定板：米白纸张、淡场地线和蓝色细边，适合打印。

## 交互与状态

- 比赛日、竞赛组别和正式批准赛果筛选保持当前 `TournamentResultCenter.vue` 行为。
- 顶部赛事名称预留为空位；日期标题采用 `YYYY.MM.DD · 比赛日`，不再固定显示“第几轮”。
- 每张比赛卡顶部显示 `HH:mm · 竞赛组别`，比赛卡内部再显示队徽、球队名称和比分。
- 主题切换只改变背景、边框、文字对比度和比分条样式，不改变赛果。
- 内容模式切换只改变战报信息密度，不改变赛果、积分或归档。
- 红黄牌开关默认关闭；开启后在相应球队球员数据下方显示红牌/黄牌小卡片、球员姓名和分钟。
- 只有 `resultStatus === approved` 的比赛进入战报；待复核、退回、异常比分继续被排除。
- PNG 导出按当前动态高度竖版画布生成，不反向修改比赛、积分、发布快照或球队数据。
- 空状态显示“当前比赛日暂无已复核赛果”，打印按钮禁用。
- 队徽缺失时使用代码生成的首字占位；不把生成图片当作真实队徽。

## 数据字段

战报继续读取现有 `resultCenter` 正式赛果字段：

`id`、`homeTeamName`、`awayTeamName`、`homeScore`、`awayScore`、`homeLogo`、`awayLogo`、`divisionName`、`roundName`、`groupName`、`matchDate`、`resultStatus`、`resolution`。

进球球员模式只消费已批准赛果的正式 `goal` 事件：

`teamId/teamName`、`playerId/playerName`、`minute`、`type`。黄牌、换人、裁判备注和待复核事件不能被推断为进球。

## 素材决策

- `01-backgrounds/flat-green-v1.png`、`flat-blue-v1.png`、`flat-white-v1.png` 是本轮三款定板对应的 ImageGen（image2.5）扁平背景；无文字、无 logo、无固定比分，可安全由代码叠加动态内容。旧的球场灯光背景保留为历史候选，不作为本轮默认主题。
- 背景只负责氛围、边缘和留白；标题、比分、队徽、进球球员、分钟、赛事名称和日期全部由正式页面代码渲染。
- 用户提供的白底、深蓝、比分加进球参考图保存在 `00-source/`，仅作为视觉研究，不直接裁切进生产页面。
- 普通高密度控件、底部导航和业务图标继续复用项目共享 SVG；本原型没有新增页面图标。
- 纵向布局优先使用 CSS/HTML 结构，导出 PNG 高度跟随实际场次；不把整张定板效果图或背景当作文本/比分截图。

## 素材缺口

- 真实球队队徽由赛事数据提供，当前原型包不携带示例队徽；正式页面需处理队徽 URL 失败和缺失状态。
- 当前 PC 截图未展示“比分＋进球球员”展开行，已用 `scorer-row-extension` 标注结构位置，正式实现需用真实事件数据验收。
- 三款背景目前都是候选 v1；正式接入前由产品负责人确认默认主题和是否保留三款主题。

## 开发边界

- 三款绿/蓝/白定板已由用户确认，包状态为 `implemented`；正式页面按定板完成动态模板接入。
- 正式实现只修改赛事战报页面及其必要的项目内图片资源，保留赛果审批、积分快照、机构权限、打印只读和 `/admin/` 资源基址。
- 不新增“手工录入进球”入口，不把战报作为第二个比分源，不改变云函数和数据模型。
