## 页面结构

页面左侧为 300 × 430 的球员卡主体，下方为等级和参赛场次指示器；右侧是球员基本信息、参赛统计、等级进度和操作按钮。此次调整只改变球员卡内部排版和卡面背景，不改变详情页路由或数据边界。

阵容编辑器会把同一球员卡缩放为 44% 显示，因此头像和主要文字需在原始卡面上保留足够视觉尺寸；本轮头像容器放大 20%，姓名增至 32px，头像底部固定在卡面腰线，不因放大而下穿信息区。

## 交互与状态

- 卡片等级由真实参赛场次计算：0–9 场铜卡、10–19 场银卡、20 场以上金卡。
- 球员照片、球队队徽、姓名、球衣名、身高体重和国旗继续来自 `PlayerCard` 的真实数据绑定。
- 等级指示器继续显示当前等级、升级所需场次和满级状态。

## 数据字段

`photoUrl`、`name`、`jerseyName`、`jerseyNumber`、`position`、`height`、`weight`、`nationality`、`appearances`、`teamLogo`。

## 素材决策

- 用户提供的 `铜卡2026.png`、`银卡2026.png`、`金卡2026.png` 均为 300 × 430 px 的透明 PNG，直接作为正式卡面使用，不再二次裁切。
- 正式页面继续使用 `web-admin-vue/public/images/铜卡.png`、`银卡.png`、`金卡.png` 三个稳定路径，避免改变组件等级映射和 `/admin/` 资源基址。
- UI 文本、等级徽章、头像、队徽均由代码渲染，不把截图裁片作为生产页面。

## 素材缺口

无阻塞缺口。三张卡面已提供完整透明画布，尺寸和正式页面固定的 300 × 430 px 一致。

## 开发边界

正式实现仅修改 `PlayerCard.vue` 的排版参数并更新三张卡面资源；保留其他未提交工作区修改，不改变登录、权限、数据读写和页面导航。
