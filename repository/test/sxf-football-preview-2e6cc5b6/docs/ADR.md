## 当前有效决策

| 日期 | 决策 | 结论 |
|---|---|---|
| 2026-10-05 | PC 服务号绑定改按自然人账号 | 已验证手机号账号生成按 `userId` 识别的服务号二维码；回调只校验账号与服务号微信一对一绑定。球队归属不推断赛事机构，多机构关系不阻断服务号个人绑定；赛事机构工作空间另行授权。本决策替代 2026-09-12“二维码同时绑定 userId+orgId、回调以机构成员关系阻断个人绑定”的部分规则 |
| 2026-10-03 | 球队建档、制卡与赛事身份核验分离 | 球队建档不收身份证、不做人证核验；制卡照片服务于球员卡和球队资料。赛事证件要求默认关闭，主办方按赛事/组别选择不收证件、投保、身份核验或两者并行，现场扫码只在身份核验启用后可选。此规则替代球队球员邀请默认强制身份证及形象照的实现。 |
| 2026-09-25 | 裁判证双通道与赛事裁判长移动排班 | 普通裁判登记仍必须提交裁判证；无证人员只能由组委会填写姓名、手机号和原因后建立赛事临时档案，本人完成同手机号验证、服务号认领和头像提交，组委会再次确认后才可排班，且资格仅限本届赛事。主办方可设置一名赛事裁判长，裁判长可在服务号安排完整执法裁判组，但不能添加或确认无证裁判、审核资格或修改赛程赛果 |
| 2026-09-25 | 赛事级日历统筹所有组别 | 赛程设置改为整届赛事的公共日期、场地和时段总控，各组别只能在总日历内覆盖场间隔、频次、休息和可用资源；赛事地图始终按全赛事真实占用校验，支持手动拖拽、Excel回填导入和自动安排三种路径；替代“固定60分钟格＋先选联合/单组编排”流程 |
| 2026-09-25 | 一个自然人账号支持多机构、多球队工作空间 | 手机号仍唯一对应一个 `User`；一个账号可通过 `organization_memberships` 加入多个机构，通过 `team_memberships` 管理多支球队。认领只新增目标球队关系，不覆盖账号原机构、不创建重复账号；当前 `workspaceId` 负责隔离数据。只有球队关系而无机构成员关系时，仅开放该球队协作空间，不开放目标机构私有经营数据。本决策替代 2026-07-31“单账号单机构”和“删除机构切换”的阶段性规则 |
| 2026-09-17 | 球队认领新增赛事级认领码 | 一个赛事生成一个认领码，球队负责人扫码后仍在小程序认领，以微信手机号快捷授权取得已验证手机号，服务端按该手机号在本赛事范围内列出可认领的待认领球队，本人明确确认后完成；手机号匹配成为唯一授权依据，服务端每次必须重新校验并照常执行有效期、赛事锁定与已认领冲突校验。逐队定向认领链接保留用于无手机号或定向发送场景，端口仍固定在小程序。本决策补充第九节规则 11/13，不推翻原表述 |
| 2026-09-16 | Word 导入直接生成正式球员和本届正式名单 | 完整报名表上传成功后无需领队再次确认，直接创建球队正式球员及本届正式名单；原始草稿继续保留审计，身份冲突阻断导入，球员未通过人证核验前仍不能进入比赛阵容。本决策替代 2026-09-13“导入改为待确认球员草稿”的确认步骤 |
| 2026-09-13 | 【已被2026-09-16新规则替代】基础版 Word 导入改为待确认球员草稿 | 历史方案为导入后再次确认球员；现已改为完整报名表直接生成正式球员和本届正式名单，身份冲突仍阻断，旧 imported_pending_claim 记录继续保留迁移审计 |
| 2026-09-13 | 人证核验与四裁判现场分工 | 正式名单前必须完成人证核验；青少年由两名助理按本方名单照片逐人确认，成人使用本场电子参赛证；第四官员初审及核验替补，主裁判最终确认、开赛、报告并手机签字 |
| 2026-09-13 | 赛事运行模式当前免费 | 简易模式与专业模式保留流程深度差异但当前均免费；不创建订单、不检查支付、不显示价格或待开通，未来新增功能是否收费另行决策 |

- 整体失败：任一组别球队/抽签/规则不完整或共享资源容量不足时，整次联合生成失败且不删除现有赛程；系统提示增加比赛日、场地或晚场，不通过删除正式场序换取排满。
- 场地制式：足球共享资源格增加`fieldFormat`，合法值仅为`5side/7side/8side/9side/11side`。排赛按`match.matchFormat === venue.fieldFormat`硬匹配；相同制式组别可混编，不同制式不得互用。历史组别缺少`matchFormat`时仅从`playersOnField`兼容推导。
- 草稿与容量干预：时间设置每步进入下一步前通过受控`saveDraft`保存赛事级白名单草稿；场地页按制式计算有效比赛日、每日资源格、赛期总容量和正式场数缺口。容量不足时禁用生成并提供增加场地、延长赛期、开启晚场或调整赛制/排名范围的入口，替代此前只在最终生成时返回容量错误的被动处理。
- 2026-08-30 补充：生成赛程不再预设唯一编排范围。向导第1步先由主办方选择“全部组别联合编排”或“按组别单独编排”；单独模式继续要求选定真实`divisionId`，容量测算、覆盖范围和生成请求都只针对该组，联合模式才允许全部已就绪组别共享资源池。选择进入白名单草稿并可刷新恢复。
- 2026-08-30 赛程地图补充：联合生成后的工作台以赛事为范围显示全部组别和全部场地，当前组别只作为业务上下文，不得隐藏其他组别占用。场地按自然编号升序并优先使用低编号兼容场地；表头与卡片分别标注场地制式和比赛制式。拖拽交换/移动复用受控`updateMatch`写入，并在客户端先执行状态、目标占用和制式兼容门禁。

## 2026-08-30：赛制与全排名统一遵循知识库V1.1
