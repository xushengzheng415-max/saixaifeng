## 1. 产品概述

### 1.1 产品定位

赛事中心（`54football.top`）是赛小蜂足球赛事管理 SaaS 平台的**综合门户与公众浏览入口**，定位为"河南足球赛事一站式内容与互动平台"。它面向公众用户（球迷、参赛者、球队/球员、自媒体），提供赛事浏览、直播观看、竞猜互动、社区侃球、榜单查询、弹幕小游戏等综合服务；同时作为**超级管理员后台**，承载赛事数据创建、认领审核、内容运营等管理职能。

赛事中心与品牌官网（`saixiaofeng.com`）形成双站协同：

| 维度 | 赛事中心 `54football.top` | 品牌官网 `saixiaofeng.com` |
|------|---------------------------|-----------------------------|
| 定位 | 综合门户 · 公众浏览 · 互动社区 · 超管后台 | 工具入口 · 创建比赛/球队/球员 |
| 用户 | 公众球迷 + 参赛者 + 自媒体 + 超管 | 赛事组织者 · 已认领数据的球队/球员 |
| 核心动作 | 看赛、竞猜、侃球、查榜、看直播 | 建赛、管队、管人、生成海报 |
| 数据流向 | 接收超管创建的"未认领"数据 → 认领 | 接收认领后数据 → 在官网管理 |

**自媒体定位**：赛事中心致力于成为**河南唯一自媒体图文直播宣传平台**，为本地足球赛事提供图文直播、集锦回放、深度报道等内容分发能力。

### 1.2 产品目标

**业务目标**
1. 建立河南足球赛事的内容分发与互动中心，汇聚本地赛事流量。
2. 通过竞猜、直播、弹幕小游戏提升用户活跃度与停留时长。
3. 通过数据认领机制，将公众赛事数据转化为赛小蜂平台正式用户。
4. 建立自媒体内容生态，形成"赛事—内容—互动—变现"闭环。

**量化指标（建议，待运营确认）**
- 日活（DAU）：赛事期间峰值目标 1 万+
- 人均停留时长：≥ 8 分钟
- 竞猜参与率：观看直播用户中 ≥ 30% 参与竞猜
- 数据认领转化率：未认领球队/球员中 ≥ 20% 完成认领

### 1.3 目标用户

| 角色 | 描述 | 核心诉求 | 使用场景 |
|------|------|----------|----------|
| 公众球迷 | 足球爱好者，主要来自河南本地 | 看赛事、看直播、竞猜、侃球、查榜单 | 日常浏览、比赛日观看直播 |
| 参赛者 | 球员、球队管理者 | 查看自己/对手赛程、阵容、战绩、认领数据 | 赛前备战、赛后复盘 |
| 球队管理者 | 球队领队/教练 | 管理阵容、认领球队数据、查看排名 | 赛事期间管理 |
| 球员 | 参赛球员 | 认领个人数据、查看个人榜、关注球队 | 认领数据、看自己表现 |
| 自媒体创作者 | 本地足球自媒体 | 图文直播、发布报道、获取流量 | 赛事现场报道 |
| 超级管理员 | 赛小蜂运营团队 | 创建赛事数据、审核认领、内容运营、平台管理 | 后台日常运营 |

## 2. 用户故事

### 2.1 公众球迷（访客/注册用户）

- **US-01**：作为球迷，我想在首页快速看到今天有哪些比赛进行中，以便决定观看哪场。
- **US-02**：作为球迷，我想按赛事类型（黄冠联赛/业余联赛等）筛选浏览，以便找到我关注的赛事。
- **US-03**：作为球迷，我想在比赛进行时观看直播，并在结束后看集锦和全场回放。
- **US-04**：作为球迷，我想参与竞猜（让球胜平负），猜中后瓜分奖池，以增加观赛趣味。
- **US-05**：作为球迷，我想在侃球区与其它球迷实时聊天，并通过弹幕小游戏为支持球队助威。
- **US-06**：作为球迷，我想查看球队榜、球员榜和人气排行，了解谁最强、谁最火。
- **US-07**：作为球迷，我想关注喜欢的球队/球员，以便及时收到他们的比赛提醒。

### 2.2 参赛者（球队/球员）

- **US-08**：作为球员，我想通过手机号认领我在赛事中的球员数据，以便在官网管理我的信息。
- **US-09**：作为球队管理者，我想认领球队数据并管理阵容，以便维护球队主页。
- **US-10**：作为参赛者，我想查看我所在赛事的赛程、对阵和积分榜，以便备战。

### 2.3 自媒体创作者

- **US-11**：作为自媒体，我想对比赛进行图文直播（实时发布文字+图片），以便粉丝跟进赛况。
- **US-12**：作为自媒体，我想发布赛事报道和集锦内容，获取平台流量分发。

### 2.4 超级管理员

- **US-13**：作为超管，我想在后台批量创建赛事、球队、球员等"未认领"数据，以便先建立内容供公众浏览。
- **US-14**：作为超管，我想审核球队/球员的认领申请，确认身份后转移数据归属。
- **US-15**：作为超管，我想管理轮播图、banner、赛事分类等运营内容。
- **US-16**：作为超管，我想管理直播调度、竞猜奖池、双币发放规则。

## 4. 页面功能详细描述

> 每个模块均包含：功能描述、移动端布局、PC 端布局、交互说明。

### 4.1 首页

**功能描述**
首页是赛事中心的流量分发核心，聚合品牌宣传、热点赛事、赛事分类入口，引导用户进入各功能模块。页面采用信息流 + 模块化卡片组合，首屏即可看到进行中比赛。

**移动端布局**（自上而下）
1. **顶部状态栏 + 搜索栏**：左 Logo「斗战足球」，右搜索图标（点击展开赛事/球队搜索）。
2. **轮播图**（P0-02）：宽度满屏，高度约 180px，自动轮播 3-5 张，3 秒切换，支持点击跳转。
3. **快速入口宫格**（P0-05）：4×2 宫格，含 7 类赛事入口 + 「全部赛事」；图标 + 文字。
   - 黄冠联赛、超勇足球杯、地市联赛、青少年赛事、业余联赛、系列赛、其他赛事、全部赛事。
4. **斗战足球上线 banner**（P0-04）：横向 banner，点击进入品牌介绍/下载页。
5. **热点赛事模块**（P0-03）：
   - Tab：「进行中 / 今日 / 即将开始」。
   - 卡片列表：每张卡片含 赛事名 + 主队 vs 客队 + 比分/时间 + 状态标签 + 「看直播/看回放」按钮。
   - 进行中卡片带红色脉冲点动画。
6. **推荐自媒体内容**（P2-07）：图文卡片流，1-2 条。
7. **底部导航**（P0-01）：首页（高亮）/ 赛事 / 侃球 / 我的。

**PC 端布局**（宽屏优势）
1. **顶部导航栏**（高度 64px）：左 Logo + 主导航（首页/赛事/侃球/我的/自媒体/榜单），右搜索框（常驻）+ 登录/头像。
2. **主区域三栏布局**（max-width 1200px 居中）：
   - **左栏（240px）**：赛事分类树（7 类赛事可展开），常驻筛选。
   - **中栏（主内容）**：
     - 顶部大轮播图（高度 360px）+ 右侧叠加快速入口浮层。
     - 下方「热点赛事」横向卡片轮播（一屏 3-4 张）。
     - 「斗战足球上线 banner」横幅。
   - **右栏（280px）**：
     - 「今日直播」时间轴列表（带预约按钮）。
     - 「人气榜 TOP5」迷你榜（球队 + 球员切换）。
     - 「热门侃球」最新 3 条聊天室热帖。
3. PC 端无底部导航，改用顶部导航 + 侧边栏。

**交互说明**
- 轮播图点击 → 跳转对应赛事/活动详情页。
- 快速入口点击 → 进入对应分类赛事列表页。
- 热点赛事卡片点击 → 进入比赛详情页。
- 进行中卡片「看直播」按钮 → 进入直播间（P1-03）。
- 下拉刷新：刷新热点赛事与直播状态。
- 搜索：支持赛事名、球队名、球员名模糊搜索。

### 4.2 赛事列表页

**功能描述**
展示全部赛事，支持按 7 类赛事分类筛选，提供搜索与排序，是用户找到目标赛事的主路径。

**移动端布局**
1. 顶部：返回 + 标题「赛事」+ 搜索图标。
2. **横向分类 Tab**（可滑动）：全部 / 黄冠联赛 / 超勇足球杯 / 地市联赛 / 青少年赛事 / 业余联赛 / 系列赛 / 其他赛事。
3. **筛选条**：状态筛选（报名中/进行中/已结束）+ 排序（最新/热度）。
4. **赛事卡片列表**：每张卡片含 赛事封面图 + 赛事名 + 赛季 + 参赛队数 + 状态标签 + 进度（如小组赛/淘汰赛）。
5. 底部加载更多。

**PC 端布局**
1. 左侧分类树（与首页左栏一致，当前分类高亮）。
2. 主区域：
   - 顶部筛选工具栏（状态、排序、搜索框）。
   - 网格卡片布局（一行 3 张赛事卡片），卡片信息更丰富（含赛程进度条、最近一轮对阵预览）。
3. 右侧：当前分类的「赛事日历」迷你组件，点击日期定位当日比赛。

**交互说明**
- 分类 Tab 切换 → 列表实时筛选。
- 卡片点击 → 进入赛事详情页（4.3）。
- 状态筛选联动列表。
- PC 端卡片 hover 显示「查看赛程」浮层按钮。

### 4.3 赛事详情页（赛况/阵容/榜单/竞猜）

**功能描述**
单个赛事的详情聚合页，顶部展示赛事概况，下方 4 个 Tab 切换不同维度信息。这是赛事内容的核心承载页。

**通用顶部（双端共用）**
- 赛事封面 banner（移动端高度 160px，PC 端 280px）。
- 赛事名 + 赛季 + 主办方 + 参赛队数 + 赛制说明。
- 4 Tab：**赛况 / 阵容 / 榜单 / 竞猜**。

#### 4.3.1 赛况 Tab

**功能描述**：展示该赛事全部比赛，按轮次/状态分组，点击进入比赛详情。

### 4.6 竞猜系统

**功能描述**
竞猜系统是核心互动玩法，用户用竞猜币参与比赛结果预测，全部猜中者瓜分奖池。竞猜币通过签到、看直播、做任务获取（不涉及真实货币，纯娱乐）。

**竞猜玩法**（P1-05~07）
1. **让球胜平负**（P1-05）：主玩法。系统给出让球数（如主队让 1 球），用户预测 让球后的胜/平/负。
2. **胜平负**（P1-06）：直接预测比赛胜/平/负，无让球。
3. **主队胜/负**（P1-07）：简化二选一，预测主队胜或负（不含平）。

**竞猜流程（核心交互）**
```
选择赛事(竞猜Tab) 
  → 选择比赛卡片 
  → 选择玩法(让球胜平负/胜平负/主队胜负) 
  → 选择预测结果(胜/平/负) 
  → 输入竞猜币数量(默认单位押注) 
  → 确认提交(扣减竞猜币, 进入奖池) 
  → 等待比赛结束 
  → 系统结算 
  → 竞猜成功(全部猜中) → 瓜分奖池, 竞猜币入账 
  → 竞猜失败 → 提示未猜中, 鼓励再战
```

**移动端布局**
- 竞猜 Tab 内：可竞猜比赛卡片列表，每张卡片显示 玩法选项（三个按钮：胜/平/负，带赔率/瓜分倍数）+ 剩余竞猜时间 + 参与人数 + 奖池总额。
- 点击选项 → 弹出竞猜确认弹层：显示 玩法 + 预测 + 投注竞猜币数（滑块或快捷金额）+ 预估瓜分 + 「确认竞猜」按钮。
- 提交成功 → 弹出「竞猜成功，等待开奖」动画页。
- 比赛结束 → 结果页：成功显示「恭喜瓜分 XX 竞猜币」+ 礼花动画；失败显示「差一点，再来一局」。

**PC 端布局**
- 竞猜大厅：左侧赛事/比赛筛选树，中间竞猜卡片网格（一屏 4-6 场），右侧「我的竞猜」+ 奖池排行。
- 竞猜卡片信息更丰富：含双方近期战绩、交锋记录、让球历史。
- 提交弹层为右侧抽屉，不遮挡卡片。

**交互说明**
- 竞猜币不足时 → 引导去任务中心获取。
- 每场比赛每人每种玩法限参与 1 次（待确认，见 6.x）。
- 奖池瓜分：全部猜中者均分奖池总额；无人猜中则奖池滚入下一期（待确认）。
- 已提交竞猜在比赛开始前可撤回（待确认）。

### 4.9 弹幕小游戏

**功能描述**
参考快手弹幕游戏，结合足球场景的互动小游戏。核心玩法「中圈开球」：球场中圈一颗足球，双方球迷通过点赞/送礼推动足球向对方球门前进，先进球方获胜。

**玩法规则**
- 每场比赛对应一个游戏房间，分主队阵营 / 客队阵营。
- 球场中央足球初始在中圈。
- 主队球迷点赞/送礼 → 足球向客队球门方向移动。
- 客队球迷点赞/送礼 → 足球向主队球门方向移动。
- 足球被推入某方球门 → 对方阵营得分，重置中圈。
- 送礼的推力大于点赞（按礼物价值换算推力）。
- 比赛结束结算阵营胜负，胜方阵营瓜分竞猜币奖池（待确认）。

**移动端布局**
- 全屏游戏界面：
  - 顶部：主队 logo + 比分（游戏比分） + 客队 logo + 在线人数。
  - 中部：俯视/侧视球场，中圈足球，两侧球门，足球随推力移动（动画）。
  - 底部：左半屏「主队点赞」按钮（连点），右半屏「客队点赞」按钮；中间「送礼」按钮。
  - 右侧：实时贡献榜（TOP3 球迷）。
- 退出按钮回到直播间/侃球页。

**PC 端布局**
- 游戏以独立窗口或直播间右栏嵌入。
- 球场横向展示，更大视野。
- 左下「主队点赞」、右下「客队点赞」、中间礼物栏。
- 右侧完整贡献榜 + 阵营进度条。

**交互说明**
- 进入游戏需选择阵营（主队/客队），选定后本场比赛不可更换。
- 点赞：免费，每点 +1 推力（有冷却防刷）。
- 送礼：消耗蜂蜜币，按价值换算推力（如 10 蜂蜜币 = 50 推力）。
- 进球动画：足球飞入球门 + 庆祝特效 + 全屏弹幕。
- 游戏结果与竞猜系统联动（待确认是否影响竞猜）。

### 4.10 双币体系

**功能描述**
双币体系是互动玩法的经济基础，两种虚拟币分别承担获取与消耗角色，均不涉及真实货币。

**双币定义**（P1-10, P1-11）
1. **竞猜币**（P1-10）：参与竞猜的凭证，仅可获取不可充值。
   - 获取途径：签到、看直播时长奖励、做任务（每日/每周任务）、活动赠送。
   - 用途：参与竞猜押注。
2. **蜂蜜币**（P1-11）：互动消耗币（名称待确认）。
   - 获取途径：活动赠送、成就奖励、（待确认是否可由竞猜币兑换）。
   - 用途：送礼、打赏、弹幕游戏推力、特殊头衔解锁。

**移动端布局**
- 个人中心资产卡：双币余额并列展示。
- 「竞猜币任务中心」页：签到日历 + 任务列表（每日/每周）+ 进度条 + 领取按钮。
- 「蜂蜜币明细」页：收支流水。

**PC 端布局**
- 个人中心资产仪表盘：双币余额 + 7 日获取趋势图 + 流水明细表。
- 任务中心独立页：任务分类看板。

**交互说明**
- 签到：每日签到得竞猜币，连续签到递增，7 日循环。
- 看直播时长：累计观看满 5/15/30 分钟分别发放竞猜币。
- 任务示例：观看 1 场直播、参与 1 次竞猜、关注 1 支球队、分享 1 次。
- 蜂蜜币消耗：送礼时实时扣减，不足时引导获取。
- 双币均不支持提现、转账（待确认）。

### 4.11 数据认领流程

**功能描述**
数据认领是赛事中心与品牌官网协同的核心机制。超级管理员在赛事中心后台创建"未认领"的球队/球员数据，球队/球员通过绑定手机号认领后，数据归属转移至官网管理。

**认领流程**
```
超管后台创建"未认领"球队/球员数据 
  → 数据在赛事中心公开展示(标记"待认领") 
  → 球队/球员在赛事中心发现自己的数据 
  → 点击"认领" → 手机号验证 
  → 提交认领申请(含身份证明) 
  → 超管后台审核 
  → 审核通过 → 数据归属转移 
  → 该球队/球员获得官网管理权限 
  → 数据标记"已认证"
```

**移动端布局**
- 球队/球员详情页：未认领显示「认领这支球队/认领我的数据」按钮。
- 点击 → 认领弹层：手机号 + 验证码 + 身份说明（如球衣号、职务）+ 上传证明。
- 提交 → 「认领申请已提交，等待审核」状态。
- 我的 → 「我的认领」：认领申请列表及状态。

**PC 端布局**
- 球队/球员详情页右侧：「认领」醒目按钮 + 认领说明。
- 认领表单为右侧抽屉，含完整信息填写。
- 我的认领管理页：表格展示申请历史。

**交互说明**
- 认领需手机号实名，一个手机号可认领 1 支球队 + 1 个球员身份（待确认）。
- 审核由超管在后台处理（P3-02），通过后数据归属写入官网账户。
- 已认领数据在赛事中心显示「已认证」徽标，链接到官网管理页。
- 认领冲突（多人申请同一数据）：按提交时间 + 审核判断。

### 4.12 超级管理员后台

**功能描述**
超级管理员后台承载赛事中心的内容运营与数据管理，是双站协同的管理中枢。后台仅 PC 端，独立于公众门户。

**后台模块**（P3-01~08）
1. **数据创建**（P3-01）：批量创建赛事、球队、球员"未认领"数据。
2. **认领审核**（P3-02）：审核认领申请，转移数据归属。
3. **运营内容**（P3-03）：轮播图、banner 配置。
4. **赛事分类管理**（P3-04）：7 类赛事分类增删改。
5. **直播调度**（P3-05）：直播排期、开播/关播控制。
6. **竞猜配置**（P3-06）：竞猜场次、奖池规则、瓜分比例配置。
7. **双币规则**（P3-07）：竞猜币/蜂蜜币获取与消耗规则配置。
8. **自媒体管理**（P3-08）：创作者账号准入、内容审核。

**PC 端布局（后台）**
- 左侧菜单树（深色侧边栏）：
  - 数据管理（赛事/球队/球员/认领审核）
  - 内容运营（轮播图/banner/分类）
  - 直播管理（排期/控制台）
  - 互动管理（竞猜配置/双币规则/弹幕游戏）
  - 用户管理（用户列表/自媒体创作者）
  - 数据看板（流量/活跃/竞猜统计）
- 顶部：管理员信息 + 站点切换（赛事中心/官网）。
- 主区域：各模块对应的表格/表单/看板。

**交互说明**
- 数据创建支持批量导入（Excel/CSV）+ 单条新建。
- 认领审核列表：展示申请人、申请对象、证明材料，一键通过/驳回。
- 直播控制台：实时查看直播状态，远程开关直播。
- 竞猜配置：设置每场竞猜玩法、奖池初始值、瓜分规则。
- 数据看板：DAU、竞猜参与率、认领转化率等核心指标可视化。

## 5. PC 端与移动端差异说明

| 维度 | 移动端 | PC 端 |
|------|--------|-------|
| **导航** | 底部 4 Tab（首页/赛事/侃球/我的） | 顶部主导航 + 左侧分类树，无底部导航 |
| **布局** | 单列纵向信息流，模块卡片堆叠 | 多栏布局（左中右三栏为主），宽屏信息密度高 |
| **首页** | 轮播 + 宫格入口 + 热点赛事列表 | 三栏：分类树 + 主内容(大轮播+横向卡片) + 右栏(直播/榜单/侃球) |
| **赛事详情** | 4 Tab 横向切换，单 Tab 全屏 | 4 Tab + 侧边联动（如阵容球场阵型图、榜单双列） |
| **直播间** | 全屏竖屏，弹幕叠加，底部输入 | 三栏：直播列表 + 大播放器 + 聊天/游戏/礼物 |
| **竞猜** | 卡片列表 + 弹层确认 | 竞猜大厅 + 卡片网格 + 右侧抽屉确认 |
| **榜单** | 单列榜单，TOP3 特殊样式 | 双列：完整表格 + 颁奖台可视化 |
| **弹幕游戏** | 全屏，左右半屏点赞 | 独立窗口/右栏嵌入，横向球场 |
| **个人中心** | 卡片 + 宫格菜单 | 左侧菜单树 + 右侧仪表盘 |
| **后台** | 不提供（仅 PC） | 完整后台管理系统 |
| **交互** | 触摸优先，下拉刷新，手势返回 | 鼠标 hover、右键、快捷键、拖拽 |
| **断点** | < 768px 移动布局 | ≥ 768px PC 布局（768-1024 适配，>1024 完整三栏） |

**响应式策略**
- 采用 Vue 3 + Element Plus 现有技术栈，基于媒体查询断点切换布局。
- 移动端优先（Mobile First），PC 端在移动端基础上扩展为多栏。
- 共用组件库，布局组件按断点条件渲染不同结构。
- 主色调保持一致（绿色系 #1B5E20 → #43A047）。

## 6. 待确认问题

> 以下问题影响设计方案与开发优先级，需与业务方/运营确认。

### 6.1 竞猜系统
1. **竞猜币与真实货币关系**：竞猜币明确不可充值，但是否允许竞猜币兑换实物奖品/优惠券？（影响是否需接入奖品商城）
2. **每场竞猜次数限制**：每人每场每种玩法限参与 1 次，还是可多次押注？（影响奖池计算与防沉迷）
3. **奖池无人猜中处理**：奖池滚入下一期，还是平分给所有参与者，还是平台回收？
4. **竞猜撤回机制**：比赛开始前是否允许撤回竞猜？撤回是否扣手续费？
5. **竞猜币初始发放**：新用户注册是否赠送初始竞猜币？数额多少？

### 6.2 双币体系
6. **蜂蜜币名称**：是否采用"蜂蜜币"命名？还是其它名称？
7. **蜂蜜币获取途径**：是否允许竞猜币兑换蜂蜜币？比例如何？
8. **双币是否可提现/转账**：确认均不可提现、不可用户间转账？
9. **蜂蜜币获取是否过于单一**：若仅靠活动赠送，是否会导致消耗过快获取不足？

### 6.3 弹幕小游戏
10. **游戏结果与竞猜联动**：弹幕游戏胜负是否影响竞猜结果/奖励？还是完全独立？
11. **游戏奖池来源**：弹幕游戏胜方瓜分的竞猜币奖池从何而来（平台发放 vs 玩家押注）？
12. **防刷机制**：点赞/送礼推力如何防止脚本刷量？冷却时间如何设定？
13. **游戏频次**：每场比赛一个游戏房间，还是整场持续还是分时段？

### 6.4 数据认领
14. **认领数量限制**：一个手机号可认领球队数 + 球员身份数的上限？
15. **认领冲突仲裁**：多人申请同一球队/球员，仲裁规则（先到先得 vs 证明材料优先级）？
16. **认领后数据同步**：认领通过后，数据从赛事中心同步到官网的时效与机制？
17. **历史数据认领**：已存在的历史球队/球员数据是否全部开放认领？

### 6.5 直播与自媒体
18. **斗战直播来源**：视频直播由平台官方统一制作，还是支持球队/自媒体自行开播？
19. **自媒体图文直播权限**：哪些主体可成为图文直播创作者？准入门槛？
20. **直播带宽与成本**：视频直播流量成本承担方，是否需限流/付费观看？
21. **回放保留期限**：集锦与全场回放保留多久？

### 6.6 社交互动
22. **聊天室管控**：是否需要敏感词过滤、实名制、举报机制？
23. **头衔体系规则**：头衔等级划分标准、权益差异？
24. **关注提醒方式**：关注球队/球员后，比赛提醒通过站内/短信/微信？频次？

### 6.7 后台与运营
25. **超管账号体系**：超管账号与公众用户账号是否分离？多超管权限分级？
26. **运营内容审核**：自媒体发布内容是否需先审后发？
27. **数据看板指标**：核心运营指标的具体定义与目标值？
28. **双站账号互通**：赛事中心与官网（saixiaofeng.com）账号是否打通（单点登录）？

### 6.8 技术与合规
29. **竞猜合规性**：竞猜币竞猜是否涉及博彩合规风险？需法务确认玩法边界。
30. **未成年人保护**：是否有年龄限制与防沉迷机制？
31. **个人信息保护**：认领涉及手机号实名，隐私政策与数据存储合规？
32. **性能要求**：直播弹幕并发量预估，弹幕游戏实时同步方案（WebSocket 推力同步）？
